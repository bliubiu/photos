## 1. 目的与边界

本文档是本项目 **ONNX 模型注册表的权威清单**，定义：

- 稳定 `id`（与 `application.toml` 的 `[models.<id>]`、`[modes.*]` 引用一致）
- 用途、默认路径、输入张量约定、所属预设
- 校验、放置、可选下载与许可证登记要求

边界：

- **处理链路零联网**；「一键下载」仅为可选前置便利（见 PRD 4.6）。
- 大文件不进 git（`.gitignore` 忽略 `models/`）；本清单只描述元数据。
- MODNet 兼容保留，**不进任何预设**；专业用户可改配置启用。

## 2. 注册表字段约定

`[models.<id>]` 必备字段（样例见 `docs/examples/application.toml`）：

| 字段 | 类型 | 说明 |
|---|---|---|
| `path` | string | 相对项目根或绝对路径的 `.onnx` 文件 |
| `sha256` | string | 64 位小写十六进制；定版前为占位全 0 |
| `input_dims` | int[] | 约定布局 `[N,C,H,W]` 或 NHWC（见下表「布局」列） |

可选字段：

| 字段 | 说明 |
|---|---|
| `download.url` | 单模型下载地址（可选） |
| `enabled` | 默认 true；false 时不参与校验与预设解析（预留） |
| `role` | 模型角色：`auto`（默认）\| `face` \| `keypoint` \| `matting` \| `parsing`。声明该模型在流水线中承担的任务；插件化注册**建议显式声明**，缺省 `auto` 表示按内置 id 推断或仅由自定义步骤使用 |
| `preprocess` | 预处理约定子表（见下），缺省沿用内置约定 `auto + unit + rgb` |

`[models.<id>.preprocess]` 声明式预处理（**接入任意 ONNX 的关键**）：

```toml
[models.my_matting]
path = "models/my_matting.onnx"
sha256 = "……64 位十六进制……"
input_dims = [1, 3, 512, 512]
role = "matting"

[models.my_matting.preprocess]
layout = "auto"   # auto（由 input_dims 推断）| nchw（[N,C,H,W]，等比缩放 + 灰边填充）| nhwc（[N,H,W,C]，直接 resize）
norm = "unit"     # unit（RGB÷255→[0,1]，内置约定）| none（保留 0-255）| { mean = [104,117,123] } | { mean_std = { mean = [0.5,0.5,0.5], std = [0.5,0.5,0.5] } }
channel = "rgb"   # rgb（内置约定）| bgr
```

校验期拦截（中文报错，不再随包静默降级）：

- `role` 非法取值、`mean`/`std` 数组长度不为 3、`std` 非全正；
- `layout` 与 `input_dims` 矛盾（声明 `nchw` 但第二维不是 3、声明 `nhwc` 但最后一维不是 3）；
- 通道维不是 3（暂不支持单通道模型）。

> `retinaface` 为唯一内置特例：等价于 `norm = { mean = [104,117,123] }` + `nchw`，由内置默认值直接声明，无需用户配置。

`[modes.<suite>]` 引用：

| 字段 | 含义 |
|---|---|
| `face` | 人脸检测模型 id |
| `keypoint` | 人体关键点模型 id |
| `matting` | 人像分割模型 id |
| `execution_provider` | `cpu` \| `cuda` |

## 4. 预设 → 模型映射

与 PRD「三套模式套件」、`application.toml` 的 `[modes.*]` 一致：

| 套件 | face | keypoint | matting | execution_provider |
|---|---|---|---|---|
| `speed` 极速 | `mtcnn`（= pnet+rnet+onet 级联） | `movnet_light` | `hivision_modnet` | `cpu` |
| `balanced` CPU 高性能（默认） | `retinaface` | `movnet_light` | `birefnet_lite` | `cpu` |
| `quality` GPU 高质量 | `retinaface` | `movnet_thunder` | `birefnet_full` | `cuda` |

> 效果对标修正（docs/08）：speed 抠图由 `rmbg` 切换为 `hivision_modnet`（人像专用、25MB）；
> `birefnet_lite` 由 DIS5K 通用权重切换为 **BiRefNet-portrait**；全部抠图模型预处理改为
> 官方约定（直接拉伸 resize + 正确归一化），详见 §3 表格说明。

M1 最小闭环仅强制 **balanced** 三件套就绪；speed / quality 可后置下载。

## 5. 校验与状态

- **惰性校验**：首次使用某模型时计算 sha256；结果按 `路径 + mtime + size → sha256` 写入 `kv_cache`。
- 文件未变则跳过全量哈希（目标：缓存命中 < 100ms，见实施计划 M0）。
- 状态枚举（`photos models` 与 `GET /models` 一致）：

| check_status | 含义 |
|---|---|
| `ready` | 文件存在且 sha256 与注册表一致 |
| `cached_ok` | 缓存命中且路径/mtime/size 未变 |
| `missing` | 文件不存在 |
| `hash_mismatch` | 文件存在但 sha256 不一致 |

缺失或校验失败 → 提示「手动放置」或「一键下载」；**禁止**把未校验文件当作就绪。

## 6. 放置与可选下载

1. **手动放置（推荐，保持离线）**：放入 **`[general].models_dir` 指向的目录**（默认：在仓库根执行时为 `项目根目录/models/`）。
   - 注册表 `path` 可写 `models/<file>.onnx` 或仅 `<file>.onnx`；实现会剥离历史 `models/` 前缀后与 `models_dir` 拼接，避免出现 `models/models/…`。
   - 自定义 `models_dir = "mymodels"` 时，文件应位于 `mymodels/`；**不要**在 `crates/photos-core/` 下再复制一份 `models/`。
2. **可选下载**：`[models.download].enabled = true` 且模型配置了 `download.url` / 镜像 `base_url` 时，CLI/WebUI 可触发；下载后仍走完整 sha256 校验。

下载配置（`application.toml`）：

```toml
[models.download]
enabled = true
timeout_secs = 120
concurrency = 2
# base_url = "https://example.invalid/models"
```

离线环境保持 `enabled = false` 或不配置镜像即可。

## 7. 模型市场与本地多版本

### 7.1 市场清单（内置 + 用户覆盖）

市场清单用于 WebUI「模型市场」展示可获取的模型，**与处理链路无关**（处理链路零联网）。清单为两层结构：

| 层 | 位置 | 说明 |
|---|---|---|
| 内置 | `crates/photos-core/resources/model_market.toml` | 用 `include_str!` 随二进制内嵌，离线可用 |
| 用户覆盖 | `<data_dir>/model_market.toml` | 存在时按 `id` + `version` **整条覆盖**内置条目，也可追加新条目 |

条目字段（`[[models]]` 数组）：

| 字段 | 说明 |
|---|---|
| `id` | 模型 id，须与 `[models.<id>]` 一致（内置条目的 id 必须已在内置注册表中） |
| `version` | 版本号，**即磁盘目录名** |
| `role` | 模型角色（同 `[models.<id>].role`） |
| `url` | 下载直链；空 = 未提供 |
| `sha256` | 目标文件 sha256；空或占位全 `0` = 未定版 |
| `size` | 文件字节数（0 = 未知，仅供展示） |
| `license` / `source` | 许可证标识与来源说明（供用户判断可用性） |
| `enabled` | 是否启用下载 |

**可下载判定** `downloadable = enabled && url 非空 && sha256 为 64 位且非占位全 0`。

内置条目**默认 url / sha256 留空且 `enabled = false`**：不随包发布第三方直链与哈希，避免地址失效或哈希不符导致下载出错误文件。WebUI 会展示清单但禁用下载按钮；用户补齐直链与哈希后（在覆盖文件里把 `enabled` 置 true）即启用该版本下载。

下载（`POST /models/download` 带 `version`）→ 落到 `models/<id>/<version>/`，仍走完整 sha256 校验。

### 7.2 本地多版本（切换与回滚）

磁盘布局：

```
models/
  birefnet_lite/
    1.0.0/birefnet-lite.onnx
    1.1.0/birefnet-lite.onnx     ← 同 id 多版本共存
```

路径解析优先级（`resolve_model_path_versioned`）：

1. 注册表 `path` 指向的文件**存在** → 直接使用（旧布局 / 单文件放置零迁移）；
2. 否则读 sqlite `prefs` 中 `model_version:<id>` 记录的激活版本 → `models/<id>/<版本>/<文件名>`；
3. 无记录 → 取版本目录内**最高版本**并回写 `prefs`。

激活版本持久化在 sqlite `prefs`（**无需新表、无需迁移**）：它属运行时状态，写回 TOML 会与「配置优先级」语义冲突。

- `GET /models/versions?id=<id>` 查看已下载版本与当前激活版本；
- `POST /models/activate` 切换 / 回滚：先确认版本目录存在，再对目标文件做 `sha256` 校验，通过才写 `prefs`（校验失败不切换）；
- 版本号比较为**逐段数值比较**（非字符串序），故 `1.10.0 > 1.9.0`。

### 7.3 自定义模型注册（插件化接入）

`POST /models/register` 把声明写入 `<data_dir>/models.custom.toml`，配置加载时作为**第二层覆盖**参与合并：

```
默认值 → application.toml → <data_dir>/models.custom.toml → 环境变量
```

要点：

- 写入前用「默认配置 + 当前生效模型表 + 候选文件」完整反序列化并 `validate()`，**校验失败不落盘**（不污染配置）；
- 同 id 重复注册视为覆盖（响应 `replaced` 为 true）；
- `sha256` 可省略：文件已存在则自动计算，否则返回 400（无法校验完整性）；
- 响应恒带 `restart_required: true`——`AppState.cfg` 为 `Arc<Config>` 不可变，**注册结果需重启进程生效**；
- `path` 可指向任意 `.onnx`（相对项目根或绝对路径）；配合 `role` + `preprocess` 即可接入**预处理约定不同**的第三方模型。

## 9. 维护规则

- 新增模型：先改本文档总表与预设映射，再改 `docs/examples/application.toml`，最后实现装载代码。
- 更换模型文件：更新 `sha256`，清相关 `kv_cache` 键，同步 CHANGELOG。
- 删除/更名 id：属破坏性变更，需 ADR 或 CHANGELOG Breaking 段说明迁移方式。
- 市场清单与注册表**同步维护**：新增可下载模型时补 `resources/model_market.toml` 条目（版本号即目录名）。
- 禁止在文档或日志中粘贴完整模型二进制；日志中的本地路径/用户信息按 `06-安全设计.md` §3.3 规则脱敏。
