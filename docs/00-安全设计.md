## 1. 文档概述

### 1.1 目的

本文档统一规范项目内配置文件敏感字段的加密存储、自动加解密逻辑、密钥管理机制，以及系统日志、输出内容的敏感数据脱敏规则，规避明文泄露、弱口令、密钥降级、数据篡改等安全风险，保障系统数据传输、存储、展示全链路安全。

### 1.2 适用范围

- **强制（M0 起）**：系统运行日志、控制台、异常信息、错误消息与 `GET /tasks*` 错误/告警 `message` 的脱敏（业务路径字段白名单见 §3.4）；`data/` 与 `logs/` 本地文件权限与最小留存。
- **预留（出现敏感配置字段时）**：配置文件中密码、密钥、授权凭证等持久化存储与加载解析。

### 1.3 核心设计原则

- **全自动无感知**：配置加载自动解密、保存自动加密，无需人工干预加解密操作
- **安全不降级**：密钥异常、密文非法时直接终止服务，禁止兜底默认密钥、零密钥降级
- **算法可扩展**：双加密算法兼容，通过算法标签自动路由解密，支持后续算法迭代扩展
- **高性能脱敏**：优先字节扫描、FSM/DFA机制，规避正则表达式性能漏洞与DoS风险
- **防循环加密**：内置加密标识识别机制，避免重复加密导致数据异常

## 2. 敏感数据加密设计

### 2.1 加密适用范围

配置文件中所有隐私、认证类敏感字段，核心包含但不限于：数据库密码、服务密钥、接口令牌、账号凭证等。所有敏感字段**禁止明文存储**，必须采用规范加密格式存储。

### 2.2 加密标识与格式规范

#### 2.2.1 外层格式

所有加密后的数据统一使用固定标识包裹，格式如下：

```Plain
ENC(base64密文)
```

系统自动识别 `ENC()` 标识，已加密数据不再重复加密，杜绝循环加密问题。非该格式的敏感字段明文，将在配置保存时自动加密转换。

#### 2.2.2 二进制载荷布局

对 `ENC()` 内部的Base64字符串解码后，得到的二进制数据固定结构如下，字段顺序、长度不可变更：

```Plain
[算法标签 1字节] + [nonce 12字节] + [ciphertext 密文] + [tag 认证标签 16字节]
```

- **算法标签（1字节）**：标识加密所使用的密码算法，用于解密自动路由
- **Nonce（12字节）**：加密随机数，每次加密全局唯一，禁止密钥+Nonce复用
- **Ciphertext**：原始明文加密后的密文内容
- **Tag（16字节）**：完整性认证标签，用于校验密文是否被篡改、伪造

### 2.3 加密算法规范

系统支持双密码算法，默认优先使用国际通用高强度加密算法，备选国密算法，通过算法标签自动区分。

| 算法标签 | 加密算法    | 优先级   | 使用说明                               |
| :------- | :---------- | :------- | :------------------------------------- |
| 0x00     | AES-256-GCM | 主选算法 | 默认全局使用，兼容性、安全性、性能最优 |
| 0x01     | SM4-GCM-SIV（待定） | 候选算法 | 适配国密合规场景，算法组合与实现待定版确认 |

解密逻辑：自动读取二进制载荷首字节算法标签，匹配对应算法执行解密，无需人工配置算法类型，无感兼容两种加密格式。

### 2.4 密钥管理机制

#### 2.4.1 密钥生成规则

系统**首次启动自动初始化密钥**，生成 **32字节真随机二进制密钥**，无人工生成、手动配置流程，杜绝弱密钥、固定密钥风险。

#### 2.4.2 密钥存储路径与权限

- 存储路径：`项目根目录/.photos/key`（`.photos` 为本地密钥目录，纯英文命名）
- 存储格式：纯二进制存储，无编码、无明文展示
- 文件权限：Unix 系统严格设置为 `0600`，仅文件所有者可读可写，其他用户无任何权限
- 管控要求：**禁止手工编辑、覆盖、删除密钥文件**

#### 2.4.3 密钥使用规则

- AES-256-GCM：使用完整32字节密钥进行加密解密
- SM4-GCM-SIV：截取32字节密钥的前16字节作为加密密钥

#### 2.4.4 密钥安全策略（强制）

密钥获取异常（文件不存在、文件损坏、密钥长度不合法、环境变量无效等），系统直接**报错终止启动/运行**，严格禁止：

- 回退默认密钥
- 使用全零密钥、空密钥兜底
- 忽略密钥异常继续运行

### 2.5 空密码处理规则

配置文件中密码字段为空字符串时，系统自动生成**高强度随机口令**赋值，严格遵循**一次生成、跨阶段一致**原则：

- 首次加载空密码时生成随机强口令并加密持久化
- 后续服务重启、配置重载保持口令一致性，不重复生成
- 杜绝空密码、弱口令带来的安全漏洞

### 2.6 加解密核心流程

#### 2.6.1 配置加载流程

1. 读取配置文件原始内容，遍历所有敏感加密字段
2. 识别字段是否为 `ENC(base64)` 标准加密格式
3. 剥离外层标识，对Base64内容解码得到二进制载荷
4. 读取首字节算法标签，匹配对应解密算法
5. 校验16字节认证Tag，验证数据完整性、合法性
6. 校验通过解密为明文，加载至系统内存；校验失败直接报错终止

#### 2.6.2 配置保存流程

1. 遍历配置所有敏感加密字段，判断是否为明文
2. 明文数据自动执行加密：生成随机12字节Nonce、加密生成密文及认证Tag
3. 拼接算法标签、Nonce、密文、Tag二进制数据，进行Base64编码
4. 包裹 `ENC()` 标识后写入配置文件
5. 已加密数据跳过加密逻辑，防止循环加密

## 3. 敏感数据脱敏设计

### 3.1 脱敏目标

对系统日志、控制台输出、异常信息、接口返回数据中的敏感信息进行脱敏展示，避免隐私数据明文泄露，脱敏不影响系统正常业务逻辑与数据存储。

### 3.2 脱敏引擎选型

优先采用**字节扫描、FSM、DFA、FSM-DFA**高效解析机制，辅以RE2正则作为补充；**禁止使用低效回溯正则**，规避大文本场景下的正则DoS攻击风险，保障脱敏性能与稳定性。敏感字段识别优先底层字节解析，精准度、性能优于传统正则匹配。

### 3.3 脱敏规则明细

#### 3.3.1 IPv4地址脱敏

- 通用规则：公网/普通内网IPv4地址，脱敏为 `*.*.后两段`，示例：`192.168.10.3` → `*.*.10.3`
- 白名单豁免：本地回环地址 `127.0.0.1`、域名 `localhost` 完整保留，不做脱敏处理

#### 3.3.2 通用敏感数据脱敏

手机号、身份证号、邮箱、密码、用户凭证等所有其他敏感数据，统一使用 `*` 号替换核心敏感内容，仅保留展示脱敏后内容，杜绝明文泄露。

#### 3.3.3 本地路径脱敏

日志、控制台输出、错误消息中出现本地路径时，遮蔽**用户目录段**（保留首字符）：

- `C:\Users\zhangsan\photos\in.jpg` → `C:\Users\z***\photos\in.jpg`
- `/home/zhangsan/photos/in.jpg` → `/home/z***/photos/in.jpg`

### 3.4 业务字段白名单（接口层）

`GET /tasks` 等**业务接口字段**（`input_path`、`outputs` 等）作为功能数据原样返回，不执行 §3.3 规则**脱敏**——理由：本案服务仅绑定回环地址、纯本地工具，前端展示完整路径是显性功能。脱敏边界锁定在**日志、控制台、异常信息、错误消息、报表**；若未来开放远程访问，须先关闭本白名单并收敛路径字段。

### 3.5 脱敏生效范围

- 系统运行日志、访问日志、错误日志
- 控制台标准输出、异常堆栈信息
- 对外接口返回数据、前端展示数据
- 运维导出报表、日志文件

脱敏仅作用于数据展示环节，**不修改内存明文、不修改配置存储密文**，保证业务正常运行。

## 4. 安全约束与禁忌规范

- 严禁硬编码密钥、默认密钥、固定盐值，所有加密密钥仅通过首次启动自动生成
- 严禁密钥文件权限放宽，禁止对外开放密钥读取权限
- 严禁重复使用同一密钥+Nonce组合加密数据
- 严禁跳过Tag完整性校验直接解密数据
- 严禁密钥异常时降级运行、静默忽略错误
- 严禁使用低效正则作为核心脱敏识别规则
- 严禁敏感字段明文持久化存储

## 5. 异常处理机制

- 密钥文件缺失、损坏、长度非法：服务终止，抛出明确密钥异常日志
- 密文格式非法、Base64解码失败：服务终止，提示密文格式错误
- 密文篡改、Tag校验失败：服务终止，提示数据被篡改风险
- 未知算法标签：服务终止，提示不支持的加密算法
