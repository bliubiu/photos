# 06-运行使用手册

> 面向使用者的操作说明：构建、配置、模型准备、三种运行方式（CLI / 桌面 WebUI / HTTP API）与故障排查。
> 关联：`02-架构设计.md` §4（配置）、`04-模型清单.md`（模型明细）、`05-API契约.md`（接口）、`docs/examples/application.toml`（配置样例）。

---

## 1. 环境要求

| 项 | 要求 |
|---|---|
| 操作系统 | Windows / Linux / macOS |
| Rust | ≥ 1.85（edition 2024） |
| 前端构建 | pnpm（项目**禁用 npm**） |
| GPU（可选） | NVIDIA 显卡 + CUDA，仅 `quality` 模式（GPU 高质量）受益 |

处理链路**纯本地离线**，除「一键下载模型」外全程零联网。

## 2. 构建

### 2.1 CLI（含真实 ONNX 推理）

```powershell
# 默认已启用 ort 特性，直接构建即可
cargo build --release -p photos-cli

# 等价显式写法（与旧文档/脚本兼容）
cargo build --release -p photos-cli --features photos-core/ort
```

产物：`target/release/photos.exe`。

> **真实推理依赖 `photos-core/ort`**：`photos-cli` 的 Cargo `default = ["ort"]` 已默认转发该 feature，正常 `cargo build -p photos-cli` 即可。若用 `--no-default-features` 构建，则不含 ONNX Runtime，`photos process` 会直接报错退出（禁止静默降级为演示结果），只能用 `--demo` 跑通链路。CUDA 质量档另加：`--features ort-cuda`。

### 2.2 桌面版（Tauri 2）

```powershell
# 1) 先构建前端产物（crates/photos-desktop/frontend/dist）
pnpm -C crates/photos-desktop/frontend install
pnpm -C crates/photos-desktop/frontend build

# 2) 构建桌面壳（需与 photos-desktop 同目录，故一并构建 CLI；CLI 默认已带 ort）
cargo build --release -p photos-desktop -p photos-cli
```

`photos gui` 会在**自身可执行文件同目录**查找 `photos-desktop(.exe)` 并拉起它。

### 2.3 运行测试

```powershell
cargo test --workspace
```

## 3. 首次准备：模型

模型默认放在**项目根目录 `models/`**（可用 `[general].models_dir` 改到别处）。模型 id、输入尺寸、许可证详见 `04-模型清单.md`。

### 3.1 查看状态

```powershell
photos models           # 表格：就绪 x/y + 每个模型状态与说明
photos models --json    # JSON（机器可读，含 summary.ready / summary.total）
```

状态含义：

| 状态 | 含义 |
|---|---|
| 就绪 | 文件存在且 sha256 与注册表一致 |
| 已缓存 | 命中 sha256 缓存（`路径 + mtime + size` 未变，跳过全量哈希） |
| 缺失 / 校验失败 | 需放置或更换模型文件 |
| 未定版 | 注册表 `sha256` 仍为占位全 `0`，**即使文件存在也不视为就绪** |

### 3.2 一键下载

```powershell
photos models download retinaface   # 按 id 下载单个模型
photos models download all          # 下载全部已启用模型（按 id 字母序串行）
```

- 下载地址来自**代码内置默认注册表**（GitHub Release / hf-mirror 镜像），可在 `application.toml` 覆写：

  ```toml
  [models.birefnet_full.download]
  url = "https://你的镜像/birefnet-full.onnx"
  ```

- 流程：流式写入同目录临时文件 `<名>.onnx.downloading` → sha256 校验（注册表非占位时）→ 原子 `rename` 替换；失败自动重试 **3 次**，超时取 `[models.download].timeout_secs`。
- 下载中断会在 `models/` 留下 `*.onnx.downloading` 残留文件，可手动删除后重试。
- **注意**：注册表 `sha256` 为占位全 `0` 时，下载后仍判为「未定版」不可用，需回填 sha256（见 `04-模型清单.md` §7）。
- 当前 `[models.download]` 的 `enabled` / `concurrency` / `base_url` **尚未接线**，仅 `timeout_secs` 生效。

### 3.3 三套模式所需模型

| 模式 | 人脸检测 | 人体关键点 | 人像分割 |
|---|---|---|---|
| `speed`（极速） | mtcnn_pnet / rnet / onet | movnet_light | rmbg |
| `balanced`（默认） | retinaface | movnet_light | birefnet_lite |
| `quality`（GPU 高质量） | retinaface | movnet_thunder | birefnet_full |

换装（虚拟试衣）额外需要 `parsing_lip`，独立于三套模式，按需惰性装载。

## 4. 配置

### 4.1 加载与优先级

默认读取**当前工作目录**的 `application.toml`，可用全局参数指定其他文件：

```powershell
photos --config D:\conf\application.toml process in.jpg
```

优先级（高 → 低）：**命令行参数 > 环境变量（`PHOTOS_` 前缀）> toml 配置文件 > 内置默认值**。

环境变量命名：`PHOTOS_` + 配置路径大写、`.`/`-` → `_`。

```powershell
$env:PHOTOS_GENERAL_LOG_LEVEL = "DEBUG"
$env:PHOTOS_MODES_BALANCED_MATTING = "rmbg"
$env:PHOTOS_GENERAL_MAX_INPUT_SIDE = "1600"
```

> 路径中的键名若本身含下划线（如 `input_dims`）无法用环境变量覆盖，请改用配置文件。

完整字段与注释见 `docs/examples/application.toml`（唯一权威样例）。

### 4.2 配置段总览

| 段 | 用途 |
|---|---|
| `[general]` | data_dir、log_dir、log_level、default_mode、models_dir、max_input_side |
| `[models.<id>]` | 模型注册表：path、sha256、input_dims、enabled、可选 download.url |
| `[models.download]` | 下载便利项：enabled、timeout_secs、concurrency、base_url |
| `[modes.speed/balanced/quality]` | face / keypoint / matting 模型引用 + execution_provider（`cpu`\|`cuda`） |
| `[sizes.<id>]` | 尺寸：名称、物理尺寸(mm)、dpi、像素 |
| `[backgrounds.<id>]` | 底色：名称 + RGB |
| `[layout."6inch"\|a4]` | 排版相纸：纸张尺寸、边距、间距 |
| `[beauty]` | 美颜默认强度：enabled、skin_smooth、brighten、whiten |
| `[inference]` | 推理资源：intra_threads、inter_threads、memory_pattern |
| `[server]` | 服务资源：max_concurrent_tasks |

|---|---|---|---|

| 常规 | `two_inch`（二寸） | 35×49 | 413×579 |
| 常规 | `small_one_inch`（小一寸） | 22×32 | 260×378 |
| 常规 | `big_one_inch`（大一寸） | 33×48 | 390×567 |
| 常规 | `small_two_inch`（小二寸） | 35×45 | 413×531 |
| 签证 | `us_visa`（美国签证） | 50.8×50.8 | 600×600 |
| 签证 | `japan_visa`（日本签证） | 45×45 | 531×531 |
| 签证 | `schengen_visa`（申根签证） | 35×45 | 413×531 |
| 签证 | `uk_visa`（英国签证） | 35×45 | 413×531 |
| 国内证件 | `passport`（护照） | 33×48 | 390×567 |
| 国内证件 | `hkmo_permit`（港澳通行证） | 33×48 | 390×567 |
| 国内证件 | `driver_license`（驾驶证） | 22×32 | 260×378 |

内置相纸 id：`6inch`、`a4`。

### 4.3 资源限制（CPU / 内存）

| 配置项 | 默认 | 作用 |
|---|---|---|
| `[general].max_input_side` | `0` | 输入图最大边长（px）。`0` = 不限制；超限等比预缩放后再进流水线，直接压降峰值内存与耗时 |
| `[inference].intra_threads` | `0` | ORT 单算子内并行线程数。`0` = 自动（通常吃满物理核）；设 `1` 可把占用压到单核 |
| `[inference].inter_threads` | `0` | ORT 算子间并行线程数。`0` = 自动；多任务并发时设 `1` 避免线程叠加 |
| `[inference].memory_pattern` | `true` | 内存复用池。关（`false`）可降峰值内存，性能略降 |
| `[server].max_concurrent_tasks` | `2` | API 最大并发处理任务数，超出排队（必须 ≥ 1） |

ONNX Runtime 不提供内存硬上限 API，峰值内存只能靠「限输入尺寸 + 关内存复用池 + 限并发」组合控制。CPU 线程总量上限 ≈ `max_concurrent_tasks × intra_threads`。

低配机器保守示例：

```toml
[general]
max_input_side = 1600

[inference]
intra_threads = 2
inter_threads = 1
memory_pattern = false

[server]
max_concurrent_tasks = 1
```

## 5. 命令行模式（CLI）

```
photos [--config <路径>] <子命令>
```

| 子命令 | 说明 |
|---|---|
| `process` | 处理证件照（单图或文件夹批量） |
| `models` | 模型状态报告 / 一键下载 |
| `serve` | 启动本地 HTTP 服务（WebUI + API） |
| `gui` | 启动桌面版（Tauri 2 窗口） |

### 5.1 `photos process`

```powershell
photos process <输入图片或文件夹> [选项]
```

| 选项 | 默认 | 说明 |
|---|---|---|
| `-m, --mode <模式>` | 配置 `general.default_mode`（`balanced`） | `speed` \| `balanced` \| `quality` |
| `--size <尺寸>` | `one_inch` | `[sizes.*]` 中的 id |
| `-b, --backgrounds <底色>` | `white` | 逗号分隔多底色，如 `red,blue,white` |
| `--rotate <角度>` | 自动 | 手动纠偏角度（度，上限 ±45） |
| `--effect` | 关 | 额外输出通用效果图（保持全图尺寸，每底色一张） |
| `--transparent` | 关 | 额外输出**透明底 PNG**（RGBA，alpha 取抠图掩膜） |
| `--bg-image <背景图>` | — | 自定义背景图本地路径：按证件照尺寸 cover 缩放居中裁切后合成，额外出 `custombg` 产物 |
| `--layout <相纸>` | 不排版 | `6inch` \| `a4`，以**首个底色**证件照铺版 |
| `--beauty` | 关 | 开启美颜（磨皮 / 提亮 / 美白）；磨皮为**分区磨皮**——按人脸关键点保护双眼/眉、鼻、嘴区域，只磨皮肤不糊五官 |
| `--beauty-smooth <强度>` | 配置 `[beauty].skin_smooth` | 磨皮强度 `0..1` |
| `--beauty-brighten <强度>` | 配置 `[beauty].brighten` | 提亮强度 `0..1` |
| `--beauty-whiten <强度>` | 配置 `[beauty].whiten` | 美白强度 `0..1` |
| `--dress <服装图>` | — | 用户服装图（智能换装，上半身） |
| `--dress-style <样式>` | — | `suit_navy`\|`suit_black`\|`shirt_white`（上半身）；`suit_full_navy`\|`suit_full_black`（全身套装） |
| `--dress-top <上衣图>` | — | 分部位贴合：上衣 |
| `--dress-bottom <下装图>` | — | 分部位贴合：下装 |
| `--dress-shoes <鞋图>` | — | 分部位贴合：鞋 |
| `-o, --out <目录>` | `data/out` | 输出目录 |
| `--demo` | 关 | 演示模式：内置 mock 引擎，不依赖模型，输出**非真实 AI 结果** |

换装参数优先级：`--dress-top/--dress-bottom/--dress-shoes`（分部位）> `--dress`（单件服装图）> `--dress-style`（程序化正装）。

#### 输入与输出

- 输入支持单文件或**文件夹递归**；识别格式：`jpg` / `jpeg` / `png` / `webp` / `bmp`。
- 每个输入产出多张，命名规约：

  | 产物 | 文件名 |
  |---|---|
  | 证件照（每底色一张） | `task_{id}_{尺寸}_{底色}.jpg` |
  | 透明底证件照（`--transparent`） | `task_{id}_{尺寸}_transparent.png` |
  | 自定义背景图（`--bg-image`） | `task_{id}_{尺寸}_custombg.jpg` |
  | 效果图（`--effect`） | `task_{id}_effect_{底色}.jpg` |
  | 排版相纸（`--layout`） | `task_{id}_layout_{相纸}.jpg` |

- 批量结束时打印汇总：成功数 / 总数、成功率、失败数、总耗时、平均耗时/张；任一文件失败会逐条打印中文错误并最终以非零码退出。

#### 常用示例

```powershell
# 最简：单图 → 一寸白底
photos process 照片.jpg

# 一次出齐三底色 + 效果图，落库到指定目录
photos process 照片.jpg -b red,blue,white --effect -o out

# 二寸蓝底 + 6 寸排版
photos process 照片.jpg --size two_inch -b blue --layout 6inch

# 批量：整目录递归，GPU 高质量模式，开美颜
photos process D:\photos\in -m quality --beauty --beauty-smooth 0.6

# 换装：藏青正装全身套装
photos process 照片.jpg --dress-style suit_full_navy

# 换装：分部位服装图（上衣/下装/鞋）
photos process 照片.jpg --dress-top top.png --dress-bottom pants.png --dress-shoes shoes.png

# 抠图增强：额外输出透明底 PNG + 自定义背景图合成
photos process 照片.jpg --transparent --bg-image D:\图片\灰底.jpg

# 无模型快速演示链路
photos process 照片.jpg --demo --effect
```

### 5.2 `photos models`

```powershell
photos models                      # 状态报告
photos models --json               # JSON 输出

```

### 5.3 `photos serve`

```powershell
photos serve [--host <地址>] [--port <端口>] [--demo]
```

| 选项 | 默认 | 说明 |
|---|---|---|
| `--host` | `127.0.0.1` | 监听地址（仅本地回环） |
| `--port` | `0` | `0` = 系统分配随机端口，端口号在启动日志中打印 |
| `--demo` | 关 | 演示引擎（非真实 AI） |

启动后终端打印 `证件照本地服务已启动：http://127.0.0.1:端口（Ctrl+C 退出）`，浏览器打开该地址即为 WebUI（同源托管前端与 API）。未编译 ort 时默认启动会失败，需显式 `--demo`。

### 5.4 `photos gui`

```powershell
photos gui
```

拉起同目录的 `photos-desktop`，由它内嵌 Axum 服务并弹出 Tauri 窗口加载 WebUI。桌面壳也可用 `PHOTOS_DEMO=1` 环境变量显式切换为演示引擎（会打印警告）。

## 6. 桌面 WebUI 模式

`photos gui`（或 `photos serve` + 浏览器打开控制台打印的地址）进入单页界面，自上而下三区 + 历史列表：

1. **1. 上传图片**：点击选择图片（支持多选批量处理）；可接受格式 `jpeg` / `png` / `bmp`。
2. **2. 参数设置**：运行模式（三选一，选项来自 `GET /config`）、尺寸、底色（可多选）、排版相纸（可选）、姿态纠偏（自动 / 手动角度），底部「开始处理」按钮提交。
3. **3. 预览与下载**：选中任务后按状态展示结果（`排队中 / 处理中 / 已完成 / 失败`）；产物可单张下载，或「打包下载全部（zip）」。
4. **历史任务**：表格展示任务 id、参数、状态、耗时、时间与操作（含打包下载）；状态、参数与产物清单持久化在本地 sqlite。

并发上限由 `[server].max_concurrent_tasks` 控制，超出部分排队等待。

## 7. HTTP API 模式

`photos serve` 启动后可直接用 HTTP 调用（契约细节见 `05-API契约.md`）。

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/tasks` | multipart 提交（`file` + `params`），返回任务 id（202） |
| GET | `/tasks/{id}` | 轮询状态、告警、产物清单 |
| GET | `/tasks/{id}/output` | 下载产物 |
| GET | `/tasks` | 历史列表 |
| GET | `/models` | 模型注册表与校验状态 |
| GET | `/config` | 驱动前端下拉的选项集 |
| GET | `/ping` | 健康检查 |

提交任务示例：

```powershell
curl -X POST http://127.0.0.1:8080/tasks `
  -F "file=@照片.jpg" `
  -F 'params={"mode":"balanced","size":"one_inch","backgrounds":["white","blue"],"effect_image":true}'
```

轮询与下载：

```powershell
curl http://127.0.0.1:8080/tasks/{id}
curl -o 白底.jpg "http://127.0.0.1:8080/tasks/{id}/output?artifact=id_photo&background=white"
curl -o 打包.zip "http://127.0.0.1:8080/tasks/{id}/output?artifact=bundle"
```

常见错误码：参数非法 `400`、文件超过 20MB `413`、模型缺失 `503`（`code=MODEL_MISSING`）、产物/任务不存在 `404`。

## 8. 数据与产物

| 路径 | 内容 |
|---|---|
| `data/photos.db` | 任务历史（sqlite，WAL 模式） |
| `data/out/` | CLI `process` 默认输出目录 |
| `data/tmp/` | API 上传的临时输入文件 |
| `logs/` | 日志文件 `photos-YYYYMMDD.log`，每日轮转，保留 32 天 |

均以 `[general].data_dir` / `log_dir` 为基准（相对当前工作目录解析）。

日志级别由 `[general].log_level` 控制（`DEBUG` / `INFO` / `ERROR`，默认 `INFO`），同时输出到文件与终端；内容为中文，不记录密码、完整身份证号、手机号。

## 9. 故障排查

| 现象 | 原因与处理 |
|---|---|
| `当前构建未启用 ONNX 推理（feature=photos-core/ort）` | 多半是 `--no-default-features` 关掉了默认 `ort`。重新 `cargo build -p photos-cli`（默认已含 ort），或显式 `--features photos-core/ort`；或临时用 `--demo` 跑链路 |
| 启动报「模型检查未通过」 | `photos models` 看具体哪个模型未就绪，按 `04-模型清单.md` 放置或 `photos models download <id>` |
| 模型状态为「未定版」 | 注册表 `sha256` 是占位全 `0`，需回填真实 sha256 后才判就绪 |
| 输出告警「角度超限，本次未自动纠偏」 | 测量角超 ±22° 阈值，按设计**降级继续出图**（不阻断）。可摆正姿态重拍，或用 `--rotate` 手动指定角度（上限 ±45°） |
| 输出告警「未检测到双眼与双肩，跳过自动纠偏」 | 关键点置信度不足（侧脸、遮挡、过小人脸）。换更清晰的正面照 |
| `models/` 下出现 `*.onnx.downloading` | 下载中断的残留临时文件（0 字节或半截），删除后重新下载 |
| `data/` 或 `logs/` 找不到 | 相对路径按**当前工作目录**解析；请在项目根目录执行，或用 `--config` 指向绝对路径的配置 |
| 端口不确定 | `photos serve` 默认随机端口，端口号在启动日志与终端输出中打印；也可显式 `--port 8080` |
| 内存占用过高 | 按 §4.3 设置 `max_input_side`、`memory_pattern = false`、降低 `max_concurrent_tasks` |
| `photos gui` 报未找到桌面版可执行文件 | 先 `cargo build -p photos-desktop`，并确保与 `photos` 可执行文件在同一目录 |
