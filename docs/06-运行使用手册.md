# 06-运行使用手册

> 面向使用者的操作说明：构建、配置、模型准备、三种运行方式（CLI / 桌面 WebUI / HTTP API）与故障排查。
> 关联：`02-架构设计.md` §4（配置）、`04-模型清单.md`（模型明细）、`05-API契约.md`（接口）、`docs/examples/application.toml`（配置样例）。

---

## 1. 环境要求

| 项 | 要求 |
|---|---|
| 操作系统 | Windows / Linux / macOS |
| Rust | ≥ 1.85（edition 2024） |
| 前端构建 | pnpm（项目**禁用 npm**） |
| GPU（可选） | NVIDIA 显卡 + CUDA，仅 `quality` 模式（GPU 高质量）受益 |

处理链路**纯本地离线**，除「一键下载模型」外全程零联网。

## 2. 构建

### 2.1 CLI（含真实 ONNX 推理）

```powershell
# 默认已启用 ort 特性，直接构建即可
cargo build --release -p photos-cli

# 等价显式写法（与旧文档/脚本兼容）
cargo build --release -p photos-cli --features photos-core/ort
```

产物：`target/release/photos.exe`。

> **真实推理依赖 `photos-core/ort`**：`photos-cli` 的 Cargo `default = ["ort"]` 已默认转发该 feature，正常 `cargo build -p photos-cli` 即可。若用 `--no-default-features` 构建，则不含 ONNX Runtime，`photos process` 会直接报错退出（禁止静默降级为演示结果），只能用 `--demo` 跑通链路。CUDA 质量档另加：`--features ort-cuda`。

### 2.2 桌面版（Tauri 2）

```powershell
# 1) 先构建前端产物（crates/photos-desktop/frontend/dist）
pnpm -C crates/photos-desktop/frontend install
pnpm -C crates/photos-desktop/frontend build

# 2) 构建桌面壳（需与 photos-desktop 同目录，故一并构建 CLI；CLI 默认已带 ort）
cargo build --release -p photos-desktop -p photos-cli
```

`photos gui` 会在**自身可执行文件同目录**查找 `photos-desktop(.exe)` 并拉起它。

### 2.3 运行测试

```powershell
cargo test --workspace
```

## 3. 首次准备：模型

模型默认放在**项目根目录 `models/`**（可用 `[general].models_dir` 改到别处）。模型 id、输入尺寸、许可证详见 `04-模型清单.md`。

### 3.1 查看状态

```powershell
photos models           # 表格：就绪 x/y + 每个模型状态与说明
photos models --json    # JSON（机器可读，含 summary.ready / summary.total）
```

状态含义：

| 状态 | 含义 |
|---|---|
| 就绪 | 文件存在且 sha256 与注册表一致 |
| 已缓存 | 命中 sha256 缓存（`路径 + mtime + size` 未变，跳过全量哈希） |
| 缺失 / 校验失败 | 需放置或更换模型文件 |
| 未定版 | 注册表 `sha256` 仍为占位全 `0`，**即使文件存在也不视为就绪** |

### 3.2 一键下载

```powershell
photos models download retinaface   # 按 id 下载单个模型
photos models download all          # 下载全部已启用模型（按 id 字母序串行）
```

- 下载地址来自**代码内置默认注册表**（GitHub Release / hf-mirror 镜像），可在 `application.toml` 覆写：

  ```toml
  [models.birefnet_full.download]
  url = "https://你的镜像/birefnet-full.onnx"
  ```

- 流程：流式写入同目录临时文件 `<名>.onnx.downloading` → sha256 校验（注册表非占位时）→ 原子 `rename` 替换；失败自动重试 **3 次**，超时取 `[models.download].timeout_secs`。
- 下载中断会在 `models/` 留下 `*.onnx.downloading` 残留文件，可手动删除后重试。
- **注意**：注册表 `sha256` 为占位全 `0` 时，下载后仍判为「未定版」不可用，需回填 sha256（见 `04-模型清单.md` §8）。
- 当前 `[models.download]` 的 `enabled` / `concurrency` / `base_url` **尚未接线**，仅 `timeout_secs` 生效。
- **WebUI / API 同样可一键下载**：参数面板在检测到模型文件缺失时给出「一键下载缺失模型（N）」按钮，等价于 `POST /models/download`（缺省下载全部缺失模型）；模型较大时该请求耗时较长，页面会保持「下载中」提示。

### 3.3 三套模式所需模型

| 模式 | 人脸检测 | 人体关键点 | 人像分割 |
|---|---|---|---|
| `speed`（极速） | mtcnn_pnet / rnet / onet | movnet_light | rmbg |
| `balanced`（默认） | retinaface | movnet_light | birefnet_lite |
| `quality`（GPU 高质量） | retinaface | movnet_thunder | birefnet_full |

换装（虚拟试衣）额外需要 `parsing_lip`，独立于三套模式，按需惰性装载。

### 3.4 自定义模型注册与本地多版本

**接入任意 ONNX（插件化注册）**：模型条目可声明 `role` 与 `preprocess`（布局 / 归一化 / 通道序），因而不再局限于「同类、同预处理」的权重替换。

- WebUI：右侧「模型管理」面板填写 `id` / 路径 / `input_dims` / 角色 / 预处理后提交，写入 `<data_dir>/models.custom.toml`；响应提示**重启服务后生效**。
- API：`POST /models/register`（契约见 `05-API契约.md` §3.15），`sha256` 可省略（文件已存在时自动计算，否则拒绝）。
- 手工配置：直接编辑 `<data_dir>/models.custom.toml`，或按 `docs/examples/application.toml` 写 `[models.<id>]` + `[models.<id>.preprocess]`。

**本地多版本（切换 / 回滚）**：把同一模型的多个版本按下述布局共存，即可随时切换：

```
models/birefnet_lite/1.0.0/birefnet-lite.onnx
models/birefnet_lite/1.1.0/birefnet-lite.onnx
```

- 解析顺序：注册表 `path` 指向的文件若存在则优先使用（旧布局零迁移）→ 否则用 sqlite `prefs` 记录的激活版本 → 无记录时取**最高版本**并回写。
- `GET /models/versions?id=birefnet_lite` 查看已下载版本与激活版本；`POST /models/activate` 切换 / 回滚（切换前做 sha256 校验，校验失败不切换）。
- WebUI「模型管理」面板每个模型提供版本下拉与「切换」按钮。

**模型市场**：`GET /models/market` 返回内置清单（随二进制内嵌，离线可用）+ 用户覆盖（`<data_dir>/model_market.toml`）。内置条目**默认 `enabled = false` 且 `url`/`sha256` 留空**，仅展示、禁用下载；复制结构到 `<data_dir>/model_market.toml` 补齐真实直链与 sha256 并置 `enabled = true` 后，即可在 WebUI 点「下载该版本」（`POST /models/download` 带 `version`）。清单字段见 `04-模型清单.md` §7。

## 4. 配置

### 4.1 加载与优先级

默认读取**当前工作目录**的 `application.toml`，可用全局参数指定其他文件：

```powershell
photos --config D:\conf\application.toml process in.jpg
```

优先级（高 → 低）：**命令行参数 > 环境变量（`PHOTOS_` 前缀）> toml 配置文件 > 内置默认值**。

环境变量命名：`PHOTOS_` + 配置路径大写、`.`/`-` → `_`。

```powershell
$env:PHOTOS_GENERAL_LOG_LEVEL = "DEBUG"
$env:PHOTOS_MODES_BALANCED_MATTING = "rmbg"
$env:PHOTOS_GENERAL_MAX_INPUT_SIDE = "1600"
```

> 路径中的键名若本身含下划线（如 `input_dims`）无法用环境变量覆盖，请改用配置文件。

完整字段与注释见 `docs/examples/application.toml`（唯一权威样例）。

### 4.2 配置段总览

| 段 | 用途 |
|---|---|
| `[general]` | data_dir、log_dir、log_level、default_mode、models_dir、max_input_side |
| `[models.<id>]` | 模型注册表：path、sha256、input_dims、enabled、可选 download.url |
| `[models.download]` | 下载便利项：enabled、timeout_secs、concurrency、base_url |
| `[modes.speed/balanced/quality]` | face / keypoint / matting 模型引用 + execution_provider（`cpu`\|`cuda`） |
| `[sizes.<id>]` | 尺寸：名称、物理尺寸(mm)、dpi、像素 |
| `[backgrounds.<id>]` | 底色：名称 + RGB |
| `[layout."6inch"\|a4]` | 排版相纸：纸张尺寸、边距、间距 |
| `[beauty]` | 美颜默认强度：enabled、skin_smooth、brighten、whiten |
| `[output]` | 输出：format（`jpg`\|`webp`）、jpg_quality（1..100）、pdf（排版是否额外出 PDF） |
| `[pipeline]` | 工作流编排：steps（步骤表）、`[pipeline.params.<步骤>]`（步骤参数）、`[pipeline.custom.<名>]`（自定义步骤） |
| `[inference]` | 推理资源：intra_threads、inter_threads、memory_pattern |
| `[server]` | 服务资源：max_concurrent_tasks |

内置尺寸 id：

|---|---|---|---|
| 常规 | `one_inch`（一寸，默认） | 25×35 | 295×413 |
| 常规 | `two_inch`（二寸） | 35×49 | 413×579 |
| 常规 | `small_one_inch`（小一寸） | 22×32 | 260×378 |
| 常规 | `big_one_inch`（大一寸） | 33×48 | 390×567 |
| 常规 | `small_two_inch`（小二寸） | 35×45 | 413×531 |
| 签证 | `us_visa`（美国签证） | 50.8×50.8 | 600×600 |
| 签证 | `japan_visa`（日本签证） | 45×45 | 531×531 |
| 签证 | `schengen_visa`（申根签证） | 35×45 | 413×531 |
| 签证 | `uk_visa`（英国签证） | 35×45 | 413×531 |
| 国内证件 | `passport`（护照） | 33×48 | 390×567 |
| 国内证件 | `hkmo_permit`（港澳通行证） | 33×48 | 390×567 |
| 国内证件 | `driver_license`（驾驶证） | 22×32 | 260×378 |
| 国内证件 | `social_security_card`（社保卡） | 26×32 | 307×378 |

自定义规格可在 `application.toml` 新增 `[sizes.<id>]` 段（`name`/`width_mm`/`height_mm`/`dpi`/`width_px`/`height_px`），CLI 与 API 即刻可用。

一次性自定义规格无需改配置：尺寸用 `px:宽x高`（DPI 取 300 用于排版换算）或 `mm:宽x高@DPI`，底色用 `#RRGGBB` / `rgb:R,G,B`。归一化为文件名安全 id 后落库与命名（`px:295x413` → `px_295x413`、`mm:35x45@300` → `mm_35x45_300`、`#ff0000` → `rgb-ff0000`），归一化 id 可再次提交。

内置底色 id：`white`（白，默认）、`blue`（蓝）、`red`（红）、`gray`（灰）。
内置相纸 id：`6inch`、`a4`。

### 4.3 资源限制（CPU / 内存）

| 配置项 | 默认 | 作用 |
|---|---|---|
| `[general].max_input_side` | `0` | 输入图最大边长（px）。`0` = 不限制；超限等比预缩放后再进流水线，直接压降峰值内存与耗时 |
| `[inference].intra_threads` | `0` | ORT 单算子内并行线程数。`0` = 自动（通常吃满物理核）；设 `1` 可把占用压到单核 |
| `[inference].inter_threads` | `0` | ORT 算子间并行线程数。`0` = 自动；多任务并发时设 `1` 避免线程叠加 |
| `[inference].memory_pattern` | `true` | 内存复用池。关（`false`）可降峰值内存，性能略降 |
| `[server].max_concurrent_tasks` | `2` | API 最大并发处理任务数，超出排队（必须 ≥ 1） |

ONNX Runtime 不提供内存硬上限 API，峰值内存只能靠「限输入尺寸 + 关内存复用池 + 限并发」组合控制。CPU 线程总量上限 ≈ `max_concurrent_tasks × intra_threads`。

低配机器保守示例：

```toml
[general]
max_input_side = 1600

[inference]
intra_threads = 2
inter_threads = 1
memory_pattern = false

[server]
max_concurrent_tasks = 1
```

### 4.4 工作流编排（`[pipeline]`）

十步流水线（读图 → 人体关键点 → 人像抠图 → 人脸检测 → 姿态求解 → 几何纠偏 → 换装 → 美颜 → 换底裁切 → 排版）可通过配置或请求参数**开关与调序**，缺省即上述顺序。

```toml
[pipeline]
steps = ["read_image", "keypoint", "matting", "face_detect", "pose", "rotate", "background"]

# 步骤参数：覆盖该步骤使用的模型 id（优先于模式套件）
[pipeline.params.keypoint]
model = "movnet_thunder"

# 自定义步骤：给内置算子起别名（可并入 steps 实现同一算子多次执行）
[pipeline.custom.我的二次抠图]
op = "matting"
```

生效优先级：请求 `params.steps`（非空）> `[pipeline] steps` > 内置默认十步。

依赖链（缺依赖在校验期报错，CLI 与 API 均返回中文提示）：`keypoint`/`matting`/`face_detect` ← `read_image`；`pose` ← `keypoint`；`rotate` ← `pose`；`dress`/`beauty`/`background` ← `rotate`；`layout` ← `background`。运行期容错：关闭 `face_detect` 时按整图居中裁切、关闭 `matting` 时跳过换底与透明底输出（仍出图），二者均在结果 `warnings` 中告警；请求了美颜 / 排版 / 换底 / 换装但对应步骤未启用时同样只告警不阻断。自定义步骤名不得与内置步骤同名。

## 5. 命令行模式（CLI）

```
photos [--config <路径>] <子命令>
```

| 子命令 | 说明 |
|---|---|
| `process` | 处理证件照（单图或文件夹批量） |
| `models` | 模型状态报告 / 一键下载 |
| `serve` | 启动本地 HTTP 服务（WebUI + API） |
| `gui` | 启动桌面版（Tauri 2 窗口） |

### 5.1 `photos process`

```powershell
photos process <输入图片或文件夹> [选项]
```

| 选项 | 默认 | 说明 |
|---|---|---|
| `-m, --mode <模式>` | 配置 `general.default_mode`（`balanced`） | `speed` \| `balanced` \| `quality` |
| `--size <尺寸>` | `one_inch` | `[sizes.*]` 中的 id；也支持自定义 `px:宽x高`（如 `px:295x413`）或 `mm:宽x高@DPI`（如 `mm:35x45@300`） |
| `-b, --backgrounds <底色>` | `white` | 逗号分隔多底色，如 `red,blue,white`；也支持自定义 RGB 的 `#RRGGBB` 或 `rgb:R,G,B` |
| `--rotate <角度>` | 自动 | 手动纠偏角度（度，上限 ±45） |
| `--effect` | 关 | 额外输出通用效果图（保持全图尺寸，每底色一张） |
| `--transparent` | 关 | 额外输出**透明底 PNG**（RGBA，alpha 取抠图掩膜） |
| `--bg-image <背景图>` | — | 自定义背景图本地路径：按证件照尺寸 cover 缩放居中裁切后合成，额外出 `custombg` 产物 |
| `--format <格式>` | 配置 `[output].format`（`jpg`） | `jpg` \| `webp`；webp 为**无损**编码，体积通常大于 jpg |
| `--quality <质量>` | 配置 `[output].jpg_quality`（`90`） | JPG 压缩质量 `1..100`，越低体积越小；对 webp 无效 |
| `--pdf` | 关 | 排版相纸额外输出 PDF（需同时 `--layout`；页面按相纸物理尺寸设定） |
| `--layout <相纸>` | 不排版 | `6inch` \| `a4`，以**首个底色**证件照铺版 |
| `--beauty` | 关 | 开启美颜（磨皮 / 提亮 / 美白）；磨皮为**分区磨皮**——按人脸关键点保护双眼/眉、鼻、嘴区域，只磨皮肤不糊五官 |
| `--beauty-smooth <强度>` | 配置 `[beauty].skin_smooth` | 磨皮强度 `0..1` |
| `--beauty-brighten <强度>` | 配置 `[beauty].brighten` | 提亮强度 `0..1` |
| `--beauty-whiten <强度>` | 配置 `[beauty].whiten` | 美白强度 `0..1` |
| `--dress <服装图>` | — | 用户服装图（智能换装，上半身） |
| `--dress-style <样式>` | — | `suit_navy`\|`suit_black`\|`shirt_white`（上半身）；`suit_full_navy`\|`suit_full_black`（全身套装） |
| `--dress-top <上衣图>` | — | 分部位贴合：上衣 |
| `--dress-bottom <下装图>` | — | 分部位贴合：下装 |
| `--dress-shoes <鞋图>` | — | 分部位贴合：鞋 |
| `-o, --out <目录>` | `data/out` | 输出目录 |
| `--demo` | 关 | 演示模式：内置 mock 引擎，不依赖模型，输出**非真实 AI 结果** |

换装参数优先级：`--dress-top/--dress-bottom/--dress-shoes`（分部位）> `--dress`（单件服装图）> `--dress-style`（程序化正装）。

换装贴合自带**光影合成**：以原图衣服区域（人像解析 mask）的明暗起伏为基准逐像素调制服装亮度，使新服装承袭原图光照方向与衣物褶皱明暗，避免"贴图感"；原图衣服区几乎全黑（无光照信息）时自动跳过调制。

#### 输入与输出

- 输入支持单文件或**文件夹递归**；识别格式：`jpg` / `jpeg` / `png` / `webp` / `bmp`。
- 每个输入产出多张，命名规约：

  | 产物 | 文件名 |
  |---|---|
  | 证件照（每底色一张） | `task_{id}_{尺寸}_{底色}.{jpg\|webp}` |
  | 透明底证件照（`--transparent`） | `task_{id}_{尺寸}_transparent.png` |
  | 自定义背景图（`--bg-image`） | `task_{id}_{尺寸}_custombg.{jpg\|webp}` |
  | 效果图（`--effect`） | `task_{id}_effect_{底色}.{jpg\|webp}` |
  | 排版相纸（`--layout`） | `task_{id}_layout_{相纸}.{jpg\|webp}` |
  | 排版 PDF（`--pdf`，需同时指定 `--layout`） | `task_{id}_layout_{相纸}.pdf` |

  扩展名随输出格式变化：`--format jpg`（默认）或 `--format webp`；透明底固定 `png`（依赖 alpha 通道）。PDF 页面按相纸物理毫米尺寸设定，内嵌 JPEG 不重采样，便于打印店直接出图。

- 单图成功后额外打印**分阶段耗时**（`分阶段耗时：读图 12.0ms · 人脸检测 88.3ms · …`，未执行的可选阶段不出现），并随任务落库到 `task_history.metrics`；失败时把错误（错误码 `INTERNAL` + 最后完成的阶段）写入 `error_log` 表。
- 批量结束时打印汇总：成功数 / 总数、成功率、失败数、总耗时、平均耗时/张；任一文件失败会逐条打印中文错误并最终以非零码退出。

#### 常用示例

```powershell
# 最简：单图 → 一寸白底
photos process 照片.jpg

# 一次出齐三底色 + 效果图，落库到指定目录
photos process 照片.jpg -b red,blue,white --effect -o out

# 二寸蓝底 + 6 寸排版
photos process 照片.jpg --size two_inch -b blue --layout 6inch

# 批量：整目录递归，GPU 高质量模式，开美颜
photos process D:\photos\in -m quality --beauty --beauty-smooth 0.6

# 换装：藏青正装全身套装
photos process 照片.jpg --dress-style suit_full_navy

# 换装：分部位服装图（上衣/下装/鞋）

photos process 照片.jpg --transparent --bg-image D:\图片\灰底.jpg

# 一次性自定义规格：35×45mm @300dpi + 自定义 RGB 底色（CLI 底色以逗号分隔，故用不含逗号的 #RRGGBB 写法）

photos process 照片.jpg --size px:295x413 -b "#0078d7"

# 输出 WebP（无损；JPEG 场景请用 --quality 控制体积）

# 压缩质量：体积更小（默认 90）
photos process 照片.jpg --quality 70

# 排版并额外输出 PDF（按相纸物理尺寸，打印店直接出图）
photos process 照片.jpg --layout a4 --pdf

# 无模型快速演示链路
photos process 照片.jpg --demo --effect
```

## 6. 桌面 WebUI 模式

`photos gui`（或 `photos serve` + 浏览器打开控制台打印的地址）进入单页界面，自上而下四区 + 历史列表：

1. **1. 上传图片**：点击选择，或把**图片 / 文件夹直接拖拽**到上传区（文件夹会递归收集其中的图片，仅受理 `jpeg` / `png` / `bmp`，非图片文件忽略）；支持多选批量处理。
2. **2. 参数设置**：顶部**「我的常用参数」**可把当前整套参数存为命名预设（同名覆盖），随时**套用 / 删除**；预设仅保存在本机浏览器 localStorage，不上传服务端。其余为运行模式（三选一，选项来自 `GET /config`）、尺寸（内置或自定义毫米宽高 + DPI）、底色（可多选，另可取色器自定义 RGB）、排版相纸（可选）、姿态纠偏（自动 / 手动角度）、**AI 美颜**（开关 + 磨皮 / 提亮 / 美白三档强度，取值 0..=1，随请求的 `params.beauty` 下发，关闭时后端不做美颜），底部「开始处理」按钮提交。
3. **3. 预览与下载**：选中任务后按状态展示结果（`排队中 / 处理中 / 已完成 / 失败`）；产物可单张下载，或「打包下载全部（zip）」；勾选**「对比原图（滑块）」**后，上传原图与处理结果在同一区域叠加，拖动分割线即可左右对照。
4. **4. 实时预览**：以最近一次产物为基准，用 Canvas 在本地实时叠加**美颜（磨皮 / 提亮 / 美白）与当前所选底色**——调节参数面板的强度滑块或底色即可即时看到近似效果。该预览为**本地近似渲染，最终以后端出图为准**；其中**底色**需要任务已输出透明底 PNG（否则仅能预览美颜，界面会提示勾选「输出透明底 PNG（带 alpha 通道）」后重新处理）。
5. **批量进度**（多图提交时出现）：显示 `已完成/总数`、进度条与预计剩余时间，逐项列出文件名与状态；单张失败不阻断其余，失败项可点**「重试失败项（N）」**按原参数重提（原文件保留在浏览器内存中）。
6. **历史任务**：表格展示任务 id、参数、状态、耗时、时间与操作（含打包下载）；顶部可按**状态 / 模式 / 尺寸 / 底色 / 起始日期**筛选（筛选在后端 SQL 完成，分页总数随筛选变化），行操作支持**「复用参数」**（一键回填该任务的参数再处理新图）与**「删除」**（连带删除磁盘产物与上传原图），顶部**「清空历史」**清空全部任务及其产物；状态、参数与产物清单持久化在本地 sqlite。
7. **运行指标**（可观测性面板）：展示任务总数 / 已完成 / 失败 / 处理中、**平均总耗时**（含样本数）、**各阶段平均耗时**（纯 CSS 条形，无图表库）与**最近错误列表**（错误码、阶段、中文信息、时间），可手动刷新；数据来自 `GET /metrics` 与 `GET /errors`。选中任务后，预览区顶部另展示该任务自身的**分阶段耗时**。
8. **模型管理**：三段——① **已注册模型**：列出每个模型的角色标签、是否自定义注册、校验状态，并对存在多版本的模型提供**版本下拉 + 切换**（切换 / 回滚）；② **模型市场**：展示 `GET /models/market` 清单（含未启用 / 已下载标记），条目可下载时提供「下载该版本」按钮；③ **注册自定义模型**：填写 `id` / 文件路径 / `input_dims` / 角色 / `sha256`（可留空）/ 预处理（布局 / 归一化 / 通道序），提交后提示**重启服务后生效**。清单与字段说明见 `04-模型清单.md` §7。
9. **工作流编排（图形化）**：按 `GET /config` 的 `pipeline.steps`（步骤中文名与依赖）与 `pipeline.effective`（当前生效步骤表）渲染**分层依赖图**——步骤为节点（显示执行序号与阶段名），`requires` 依赖为**贝塞尔连线**（箭头由被依赖步骤指向依赖它的步骤，即执行方向），鼠标悬停节点时其出入连线高亮。节点内「关闭」停用该步骤（停用后落入下方「已关闭步骤」灰区，可一键「启用」）；**同一行内**用 `←`/`→` 调序（跨行交换会破坏依赖，服务端会拒绝）；「恢复默认」置空 `params.steps` 回到服务端配置 / 内置默认十步。节点位置变化带 300ms 过渡动画，依赖缺失的节点以红边 + 脉冲提示，面板底部汇总「依赖提示」与「已开启美颜 / 已选排版 / 已选透明底或自定义背景但对应步骤未启用」的冲突提示（提交后服务端同样会中文告警）。调整结果随 `params.steps` 下发，属一次性请求参数。

并发上限由 `[server].max_concurrent_tasks` 控制，超出部分排队等待。

## 7. HTTP API 模式

`photos serve` 启动后可直接用 HTTP 调用（契约细节见 `05-API契约.md`）。

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/tasks` | multipart 提交（`file` + `params`），返回任务 id（202） |
| GET | `/tasks/{id}` | 轮询状态、告警、产物清单与提交参数 |
| DELETE | `/tasks/{id}` | 删除任务，并连带删除磁盘产物与上传原图 |
| GET | `/tasks/{id}/output` | 下载产物 |
| GET | `/tasks/{id}/input` | 读取上传原图（供对比展示） |
| GET | `/tasks` | 历史列表（支持 `status`/`mode`/`size`/`background`/`since` 筛选与分页） |
| DELETE | `/tasks` | 清空历史任务及其产物 |
| GET | `/models` | 模型注册表与校验状态（含角色 / 版本 / 内置标记） |
| POST | `/models/download` | 一键下载（缺省为全部缺失）；`version` 有值时按市场清单下载指定版本 |
| GET | `/models/market` | 模型市场清单（内置 + 用户覆盖，标注可下载与本地状态） |
| POST | `/models/register` | 注册自定义模型（写入 `<data_dir>/models.custom.toml`，重启生效） |
| GET | `/models/versions` | 指定模型的已下载版本与激活版本（`?id=...`） |
| POST | `/models/activate` | 切换 / 回滚模型激活版本 |
| GET | `/config` | 驱动前端下拉的选项集 |
| GET | `/metrics` | 可观测性指标：任务统计、平均耗时、各阶段平均耗时、错误总数 |
| GET | `/errors` | 错误上报记录（倒序，`limit` 默认 20，上限 200） |
| GET | `/ping` | 健康检查 |

提交任务示例：

```powershell
curl -X POST http://127.0.0.1:8080/tasks `
  -F "file=@照片.jpg" `
  -F 'params={"mode":"balanced","size":"one_inch","backgrounds":["white","blue"],"effect_image":true}'
```

轮询与下载：

```powershell
curl http://127.0.0.1:8080/tasks/{id}
curl -o 白底.jpg "http://127.0.0.1:8080/tasks/{id}/output?artifact=id_photo&background=white"
curl -o 打包.zip "http://127.0.0.1:8080/tasks/{id}/output?artifact=bundle"
```

可观测性查询：

```powershell
curl http://127.0.0.1:8080/metrics
curl "http://127.0.0.1:8080/errors?limit=50"
```

模型市场与版本管理：

```powershell
curl http://127.0.0.1:8080/models/market                      # 市场清单（默认均不可下载）
curl "http://127.0.0.1:8080/models/versions?id=birefnet_lite" # 已下载版本与激活版本
curl -X POST http://127.0.0.1:8080/models/activate `
  -H "Content-Type: application/json" `
  -d '{"id":"birefnet_lite","version":"1.0.0"}'               # 切换 / 回滚
curl -X POST http://127.0.0.1:8080/models/register `
  -H "Content-Type: application/json" `
  -d '{"id":"my_matting","path":"models/my_matting.onnx","input_dims":[1,3,512,512],"role":"matting"}'
```

工作流步骤编排（`steps` 为步骤 id 数组，顺序即执行顺序）：

```powershell
# 关闭换装 / 美颜 / 排版（只出证件照与换底）
curl -X POST http://127.0.0.1:8080/tasks `
  -F "file=@照片.jpg" `
  -F 'params={"mode":"balanced","size":"one_inch","backgrounds":["white"],"steps":["read_image","keypoint","matting","face_detect","pose","rotate","background"]}'
```

常见错误码：参数非法 `400`（含未知 / 重复 / 依赖缺失的工作流步骤）、文件超过 20MB `413`、模型缺失 `503`（`code=MODEL_MISSING`）、产物/任务不存在 `404`、注册声明非法 `400`（`code=MODEL_REGISTER_INVALID`）、模型版本不存在 `400`（`code=MODEL_VERSION_UNKNOWN`）。

## 8. 数据与产物

| 路径 | 内容 |
|---|---|
| `data/photos.db` | 任务历史与错误上报（sqlite，WAL 模式；表 `task_history` / `error_log` / `kv_cache` / `prefs`） |
| `data/out/` | CLI `process` 默认输出目录 |
| `data/tmp/` | API 上传的临时输入文件 |
| `logs/` | 日志文件 `photos-YYYYMMDD.log`，每日轮转，保留 32 天 |

均以 `[general].data_dir` / `log_dir` 为基准（相对当前工作目录解析）。WebUI/API 的**删除单条**或**清空历史**会连带删除对应任务在上述输出目录与上传目录中的文件（仅限目录内文件，路径越界一律跳过）。

日志级别由 `[general].log_level` 控制（`DEBUG` / `INFO` / `ERROR`，默认 `INFO`），同时输出到文件与终端；内容为中文，不记录密码、完整身份证号、手机号。

## 9. 故障排查

| 现象 | 原因与处理 |
|---|---|
| `当前构建未启用 ONNX 推理（feature=photos-core/ort）` | 多半是 `--no-default-features` 关掉了默认 `ort`。重新 `cargo build -p photos-cli`（默认已含 ort），或显式 `--features photos-core/ort`；或临时用 `--demo` 跑链路 |
| 启动报「模型检查未通过」 | `photos models` 看具体哪个模型未就绪，按 `04-模型清单.md` 放置或 `photos models download <id>` |
| 模型状态为「未定版」 | 注册表 `sha256` 是占位全 `0`，需回填真实 sha256 后才判就绪 |
| 输出告警「角度超限，本次未自动纠偏」 | 测量角超 ±22° 阈值，按设计**降级继续出图**（不阻断）。可摆正姿态重拍，或用 `--rotate` 手动指定角度（上限 ±45°） |
| 输出告警「未检测到双眼与双肩，跳过自动纠偏」 | 关键点置信度不足（侧脸、遮挡、过小人脸）。换更清晰的正面照 |
| 输出告警「疑似侧脸（估算偏转 xx°），建议提供正面照」 | 由左眼/右眼/鼻尖估算的 yaw 超 ±30°（仅告警，**不阻断出图**）。侧脸照的抠图与姿态纠偏效果有限，建议换正面照重拍 |
| 输出告警「未检测到双肩，仅用头部角度」/「未检测到双眼，仅用肩线角度」 | 关键点部分缺失，自动降级为单路角度（仍会出图）。半身/坐姿照片常见双髋缺失，此时自动退回「头部 0.6 + 肩线 0.4」两路融合，**无告警** |
| `models/` 下出现 `*.onnx.downloading` | 下载中断的残留临时文件（0 字节或半截），删除后重新下载 |
| `data/` 或 `logs/` 找不到 | 相对路径按**当前工作目录**解析；请在项目根目录执行，或用 `--config` 指向绝对路径的配置 |
| 端口不确定 | `photos serve` 默认随机端口，端口号在启动日志与终端输出中打印；也可显式 `--port 8080` |
| 内存占用过高 | 按 §4.3 设置 `max_input_side`、`memory_pattern = false`、降低 `max_concurrent_tasks` |
| `photos gui` 报未找到桌面版可执行文件 | 先 `cargo build -p photos-desktop`，并确保与 `photos` 可执行文件在同一目录 |
