## 一、核心算法能力增强（直接提升出图质量）

### 1. 抠图质量：去色边 + 透明背景输出
当前抠图后处理只做了 `阈值化 → 形态学开运算 → 高斯羽化`。AGENTS.md 提到"杜绝白边、黑边、漏边"，但代码中未专门实现。

> **状态：✅ 已落地（2026.09.18.0）**——三项全部实现，见 CHANGELOG `[2026.09.18.0]`。算子位于 `crates/photos-core/src/vision/blend.rs`（`estimate_background_color` / `decontaminate` / `fit_cover` / `composite_with_image` / `to_rgba`）与 `crop.rs`（`crop_resize_rgba`）；链路直通 CLI `--transparent`/`--bg-image`、API `params.transparent`/`params.bg_image` 与桌面 WebUI 参数面板。

- **去色边（Decontamination）**：发丝/边缘像素常混入背景色，需要基于 mask 的 alpha 估计做颜色解混（`decontaminate = (fg - bg*(1-α)) / α`），消除白边/黑边。
- **透明背景 PNG 输出**：当前只输出 JPG 合成图。应支持输出带 alpha 通道的 PNG（人像抠图结果直接作为 alpha），这是"自定义背景图替换"的前置能力。
- **自定义背景图替换**：AGENTS.md 明确列出但代码未实现——将背景图按证件照尺寸缩放/裁切后与人像合成。

### 2. 姿态纠偏：全身校正 + 画面居中
当前只融合"双眼角 + 肩线角"。可扩展：

> **状态：⚙️ 躯干垂直度校正 + 侧脸告警已落地（2026.09.18.9）**——`vision/geometry.rs` 新增 `torso_angle`（肩中点 → 髋/膝中点连线相对竖直的倾角，符号与头部/肩线角一致）与 `fused_angle_with_torso`（0.5 头部 + 0.3 肩线 + 0.2 躯干，权重和为 1）；`KeypointSet` 新增 `hips`/`knees`/`lower_mid`/`shoulder_mid`，髋部缺失自动退回膝部，下半身全部缺失时**保持原「0.6 头部 + 0.4 肩线」两路融合不变**（半身证件照无行为变化）。侧脸检测由 `yaw_from_landmarks`（左眼/右眼/鼻尖：鼻尖相对双眼中点的水平偏移 ÷ 双眼半间距，近似 `sin(yaw)`，自归一化不依赖随偏转同时收缩的脸框宽度）实现，|yaw| > 30° 时输出告警「疑似侧脸（估算偏转 xx°），建议提供正面照」，仅告警不阻断出图。画面居中的平移校正仍待后续。

- **躯干垂直度检测**：利用 MoveNet 的髋部/膝盖关键点计算躯干倾斜角，与头部/肩部做加权融合，修复高低肩之外的侧身倾斜。
- **画面居中矫正**：基于人脸框中心与画面中心的偏移，做水平/垂直平移校正（AGENTS.md 提到但未实现）。
- **侧脸检测与告警**：利用双眼 x 坐标差与脸宽的比例判断 yaw 角，超过阈值（如 30°）告警"请提供正面照"。

### 3. 美颜：分区磨皮 + 五官保护

> **状态：✅ 已落地（2026.09.18.3）**——新增 `vision::beauty::{FeatureRegion, face_feature_regions, feature_protect_mask, apply_beauty_protected}`：由 RetinaFace/MTCNN 5 关键点（双眼、鼻尖、两嘴角）推导「双眼含眉 / 鼻 / 嘴」4 个椭圆保护区并高斯羽化，磨皮按 `1 - 保护掩膜` 加权（提亮/美白不受影响）；检测结果位于原图坐标系，流水线按纠偏矩阵同步变换关键点后再生成掩膜（`beauty_protect_mask`），保证纠偏后五官仍被准确避让。牙齿美白/眼睛提亮/肤色直方图对齐仍待后续。

当前美颜对全图做双边滤波，会模糊五官细节。可增强：
- **分区磨皮**：基于人脸关键点生成"五官保护 mask"（眼/眉/嘴/鼻区域不磨皮），只对皮肤区域磨皮，保留五官锐度。
- **牙齿美白 / 眼睛提亮**：利用人脸关键点定位牙齿/眼睛区域做局部提亮。
- **肤色均衡**：当前 `whiten` 只是简单拉白，真正的肤色均衡应将肤色直方图对齐到目标肤色（如标准证件照肤色）。

### 4. 换装：真实试衣 + 光影合成

> **状态：⚙️ 光影合成已落地（2026.09.18.8）**——`vision/dressing.rs` 新增光影场 `shading_factors`：取原图衣服区域（人像解析 mask）像素亮度 → 相对区域均值归一化 → 高斯模糊平滑（去衣物纹理噪声、保留大范围光照方向）→ 强度加权（0.6）并钳制 `0.6..=1.4`，逐像素调制贴合服装亮度后再做 alpha 合成，使换装结果承袭原图光照方向与衣物褶皱明暗；原图衣服区无有效像素或亮度均值近 0（如黑色上衣）时不做调制。人体姿态感知纹理映射、更多职业装模板仍待后续。

当前换装是"服装图等比缩放贴到衣服 mask 上"，效果偏平。可增强：
- **人体姿态感知的纹理映射**：根据肩部/腰部关键点计算服装的缩放/倾斜角度，使服装跟随人体姿态。
- **光影合成**：根据原图光照方向（可从人脸高光区域估算）给服装叠加阴影/高光，使换装更自然。
- **更多职业装模板**：当前只有 5 种程序化正装，可扩展衬衫+领带、护士服、校服、军装等证件照常用职业装。

## 二、产品功能丰富（提升业务覆盖面）

### 1. 尺寸规格库扩展
当前只有一寸、二寸、小一寸。证件照业务的核心价值之一是"全规格覆盖"：

> **状态：✅ 已落地（2026.09.18.1）**——内置规格由 3 个扩到 15 个（常规 5 / 签证 4 / 国内证件 5 / 考试报名 1），见 `config.rs` 的 `default_sizes()` 与 `docs/examples/application.toml`；自定义规格继续由 `[sizes.<id>]` 配置段支持。

- **各国签证照**：美国（2×2英寸）、日本（4.5×4.5cm）、申根（3.5×4.5cm）、英国等。
- **国内证件**：护照、驾驶证、社保卡、居住证、港澳通行证。
- **考试报名**：各类公考/教资/艺考报名照。
- **自定义尺寸**：前端允许用户输入宽高(mm) + DPI 生成规格。

### 2. 底色体系完善

> **状态：✅ 已落地（2026.09.18.6）**——自定义 RGB 底色与自定义尺寸均支持，见 `config.rs` 的 `resolve_background` / `resolve_size`：底色接受 `#RRGGBB` / `rgb:R,G,B`，尺寸接受 `px:宽x高`、`mm:宽x高@DPI`，受理时归一化为文件名安全 id（`rgb-ff0000` / `px_295x413` / `mm_35x45_300`）后落库与命名，解析幂等；CLI `--size`/`--backgrounds`、API `params.size`/`params.backgrounds` 与桌面参数面板（取色器 + 毫米宽高/DPI 输入）三处透明可用。标准底色扩充、渐变底仍待后续。

- **标准底色扩充**：渐变蓝（部分签证要求）、特定 RGB 值的官方标准色（如中国签证照的蓝 `[43,91,159]`）。
- **自定义 RGB 底色**：前端提供取色器，用户输入任意 RGB。
- **透明背景**：输出 PNG 透明底，方便用户自行合成。

### 3. 排版引擎增强
- **更多相纸规格**：5寸、7寸、3R/4R/5R 等国际通用规格。
- **自定义排版参数**：边距、间距、行列数可调。
- **混排**：同一张相纸排放不同底色或不同尺寸的证件照。
- **PDF 导出**：排版结果输出为 PDF，便于打印店直接使用。

### 4. 批量处理体验

> **状态：✅ 进度可视化与失败重试已落地（2026.09.18.7）**——前端新增 `components/BatchPanel.tsx` 与 store 的批量状态机（`batch: BatchItem[]`，逐项维护 `上传中/处理中/已完成/失败`）：展示 `已完成/总数`、进度条与按已完成项平均耗时估算的剩余时间，逐项列出文件名与状态；单张上传/处理失败不阻断其余，失败项（上传失败的已保留原文件、处理失败的按原参数）可「一键重试失败项（N）」。批量报告导出（CSV）、参数显式复用仍待后续。

## 三、用户体验与工程完善

### 1. 前端交互升级
- **实时预览**：当前是"提交→轮询→出图"。可对轻量化操作（换底色、裁切、美颜强度）做前端实时预览，重操作（抠图/换装）仍走后端。
- **前后对比滑块**：原图 vs 处理结果拖动对比。
- **拖拽上传 + 多文件**：当前已有多文件，但可支持拖拽文件夹。
- **美颜/换装滑块**：参数调节时实时反馈（配合实时预览）。

### 2. 推理引擎复用（性能）

> **状态：✅ 已落地（2026.09.18.2）**——新增进程级引擎池 `crates/photos-api/src/engine_pool.rs`（`EnginePool` + 借用守卫 `EngineLease`），容量取 `[server] max_concurrent_tasks`；`EngineFactory` 改为按尺寸借出引擎，生产工厂 `production_engine_factory(&Config)` 池化，任务结束自动归还，已装载模型会话（含按需加载的换装解析模型 `parsing_lip`）常驻复用；演示/测试引擎经 `EngineLease::owned` 保持一次性（按尺寸回放语义不变）。CLI 批量处理原本已复用同一引擎，无需改动。

[handlers.rs](file:///d:/19-Training/Rust/photos/crates/photos-api/src/handlers.rs#L507-L518) 中每个任务都通过 `engine_factory` 新建引擎，模型加载开销大。建议：
- **进程级引擎池**：按模式套件缓存已加载的 OrtEngine，任务从池中借用，避免重复加载模型。
- **换装模型常驻**：`parsing_lip` 当前按需加载，换装频繁时可常驻。

### 3. 模型一键下载（前端闭环）

> **状态：✅ 已落地（2026.09.18.5）**——新增 `POST /models/download`（`crates/photos-api/src/handlers.rs::download_models`）：`ids` 缺省时下载全部「文件缺失」模型，已存在文件跳过视为成功，单个失败不阻断其余并逐项返回中文原因；下载走 `spawn_blocking` 不占用异步运行时线程。参数面板的模型缺失提示改为「一键下载缺失模型（N）」按钮，下载中显示进度提示，完成后自动刷新 `GET /models` 就绪状态。

当前模型缺失时前端只提示用 CLI 下载。可在前端增加"一键下载"按钮，调用后端的下载端点（需新增 `POST /models/download`）。

### 4. 可观测性
- **分阶段耗时**：pipeline 中检测/抠图/纠偏/换底各阶段耗时记录到任务详情，便于性能分析。
- **告警分级**：当前 warnings 是字符串列表，可结构化（code + message），前端可按类型展示。

### 5. 输出格式
- **多格式导出**：JPG（当前）、PNG（透明底）、WebP（压缩）。
- **质量参数**：JPG 压缩质量可调（当前固定）。
