## 1. 总则

- 采用 TDD：每个功能先写测试（红），再实现至通过（绿），视需重构。
- 每个里程碑结束必须：全部测试通过、`cargo fmt`/`clippy` 干净、创建 git commit。
- 每次变更后更新 `CHANGELOG.md` 对应版本段。
- 不可逆技术决策写入 `docs/adr/`。

## 3. M0 骨架

### 3.1 任务分解

1. `git init`、`.gitignore`（忽略 `models/` 大文件、`data/`、`logs/`、`target/`、`node_modules/`）。
2. Cargo workspace：`photos-core` / `photos-api` / `photos-cli` / `photos-desktop` 四 crate（desktop 暂为占位）。
3. `application.toml` 解析：全局段 + 三套件模型映射 + 模型注册表 + 尺寸集/底色集/布局 + 美颜参数。
   - 样例夹具：`docs/examples/application.toml`（字段以 `02-架构设计.md` §4.1 为准）。
   - 优先级合并：命令行 > 环境变量（`PHOTOS_*`）> toml > 默认值（实现 `MergeConfig`）。
4. 日志：`tracing` + 文件日轮转 + 终端输出，格式对齐规范；敏感脱敏写日志层。
5. 存储：sqlite 初始化（WAL），建 `task_history` / `kv_cache` / `prefs`。
6. 模型管理：读注册表 → 生成模型状态报告；惰性校验（首次 sha256 + kv 缓存）；清单字段以 `docs/04-模型清单.md` 为准。
7. `photos models` 子命令输出各模型状态（就绪/缺失/校验失败/缓存命中）。

### 3.2 验证

- `photos models` 在无模型目录时给出缺模型清单与「放置/下载」指引。
- 放入合法模型文件后，「校验→缓存→再启动命中缓存<100ms」。
- 单元测试：配置合并优先级、日志格式、sqlite 表、校验缓存命中逻辑。
- 集成测试：CRUD task_history、kv_cache。

## 4. M1 核心链路

### 4.1 任务分解

1. **推理封装**（`photos-core`）：`ort` 装载 ONNX、CPU/GPU provider 由模式决定；统一 `InferenceInput{张量}` → `InferenceOutput`。
2. **人脸检测**：RetinaFace 前/后处理（bbox + 5 点），纯 Rust 实现 NMS、坐标还原。
3. **人体关键点**：MoveNet-Lightning 前/后处理（17 点）。
4. **姿态角度求解**：头部角 / 肩线角 → 融合角 → 自动阈值（22°）/ 手动覆盖（±45°）分支。
5. **AI 人像抠图（BiRefNet-Lite）**：BiRefNet-Lite 推理 → mask（阈值化 + 形态学开运算去噪，`imageproc`）。
6. **同步几何纠偏**：同一仿射矩阵变换原图（线性插值）与 mask（最近邻）。
7. **换底色 + 裁切**：alpha 混合器（自研逐像素）；基于人脸框的头顶/下巴定界 + 中心裁切 + resize。
8. **pipeline 编排器**：`Photo → Request → Result`，先只支持单底色、无排版、无美颜（占位空实现）。
9. `photos process` 子命令：单图模式打通。

### 4.2 验证

- 系统测试：一张测试人像 → `photos process -m balanced in.jpg -o out/` → 输出 1 张标准证件照文件。
- 单元覆盖：角度求解（含阈值/覆盖边界）、仿射矩阵、mask 形态学、混色、裁切。
- 集成：pipeline 端到端（mock 推理输出回放固定张量亦可）。

### 4.3 前置条件

- 需要 RetinaFace / MoveNet-Lightning / BiRefNet-Lite 的 `.onnx` 模型文件放入 `models/`。
- 若无现成模型：M1 内先实现「缺模型提示 + 一键下载（可选）」，用最小可用模型（如 MTCNN + RMBG）先行打通链路，再替换 BiRefNet。

## 5. M2 / M3 / M4 概览

### M2 产物完备
- 多底色（1..N）、通用效果图出口、6寸/A4 排版引擎、文件夹批处理、输出命名规约、`--rotate`/`--layout`/`--beauty` 参数面补齐。

### M3 服务与桌面
- `photos-api`：按 `02-架构设计.md` §7 最小契约实现（含任务状态机 `queued|running|succeeded|failed`）；OpenAPI 可从契约导出。
- `photos serve` 子命令；前端（React 19 + Tailwind + Zustand）单页三区 + 历史列表。
- `photos-desktop` 壳：内嵌 Axum + WebView；前端产物打包进壳。
- 批量队列、打包下载。

### M4 增强
- 美颜算子（双边滤波磨皮/提亮/锐化）、换装（实验）、CUDA provider 开关、批量报告（耗时/成功率）、体积与内存优化。

## 6. 测试策略（贯穿）

| 层级 | 手段 | 目标 |
|---|---|---|
| 单元 | `cargo test`（算子、角度、配置合并、缓存、校验） | 100% 覆盖算法与状态机 |
| API | `axum` 集成测试（契约、错误中文、脱敏） | 全部端点 |
| 集成 | pipeline 全链路（含 mock 推理张量回放） | 全链路稳定 |
| 系统 | CLI/WebUI 端到端（临时目录、真实小模型） | 验收场景 |
