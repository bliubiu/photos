# 项目架构设计

> 版本：2026.09.16.0（CalVer）
> 关联：`01-PRD产品需求说明书.md`、`CONTEXT.md`、`docs/adr/0001-纯Rust图像栈.md`

## 1. 整体架构

### 1.1 工作区形态（四 crate）

```
photos
├── photos-core      (lib) 领域模型 + pipeline 编排 + 图像/推理实现。不依赖任何 HTTP / Tauri。
├── photos-api       (lib) Axum 路由层，挂 photos-core。
├── photos-cli       (bin) photos process / serve / models。serve 复用 photos-api。
└── photos-desktop   (bin) Tauri 壳：拉起内嵌 Axum + 打开 WebUI 窗口。唯一依赖 Tauri。
     └── 前端 React 构建产物（挂入桌面壳资源）
```

依赖方向（单向）：

```
photos-cli ──► photos-api ──► photos-core
photos-desktop ──► photos-api ──► photos-core
```

- `photos-core` 不 import 任何 crate 外的 Web 依赖；`photos-desktop` 不依赖 `photos-cli`。
- 前端契约（REST/JSON）由 `photos-api` 定义，CLI 与 WebUI 共享同一份，天然一致。
- 发布产物：CLI 单一二进制（无 GUI、体积小）；桌面壳按平台打包。

### 1.2 运行进程拓扑

```
┌─ CLI 模式 ─────────────────────────────┐
│  photos process / photos serve         │
│   └ photos-cli ──► photos-api ──► core │
└────────────────────────────────────────┘
   （serve：localhost HTTP，无 GUI，无头可运行）

┌─ WebUI 模式 ───────────────────────────┐
│  Tauri 主进程 ─ 内嵌 Axum (127.0.0.1:随机端口)   │
│      │  HTTP/JSON(fetch)                        │
│      └ React WebView ──► photos-api ──► core     │
└────────────────────────────────────────┘
```

关键决策：**前后端通信唯一通道为本地 HTTP**（非 Tauri IPC）。理由：单一契约层、可 OpenAPI 文档化、CLI/serve/WebUI 三入口共享同一 API。localhost 往返亚毫秒级，高频率交互（预览滑块）以 200ms 防抖即可满足。

### 1.3 领域模型（任务三件套）

```
Photo    输入照片：文件路径 或 内存字节 + 源格式
Request  处理请求：模式套件(Speed/Balanced/Quality) + 目标尺寸标准
                  + 底色列表(1..N) + 美颜参数 + 纠偏策略(自动/手动override)
                  + 排版规格 + 效果图开关
Result   处理结果：通用效果图(可选) + 每底色一张证件照 + 排版图(可选)
```

- 单请求多产物：重计算（人脸/姿态/抠图/纠偏）一次，换底色与裁切为轻合成，按底色数量重复。
- 产物统一落 `data/out/` 引用路径，不落数据库字节。

### 1.4 模型管理（目录发现 + 校验 + 可选下载）

- 模型根目录：`项目根目录/models`。
- 注册表：`application.toml` 的 `[models.<id>]` 段。
- 校验：惰性 + 缓存（见 4.2 存储设计）。
- 流程：

```
启动/首用某模型头一次 → 检查注册表是否存在对应条目
   ├─ 文件不存在或 sha256/维度不符 → 提示「手动放置」或「一键下载」
   └─ 通过 → 缓存 (路径+mtime+size → sha256) 到 kv_cache，
            后续文件未变则跳过全量哈希
```

## 2. 技术栈

| 层 | 选型 | 说明 |
|---|---|---|
| 推理 | `ort`（ONNX Runtime 绑定） | CPU/CUDA 自适应，由模式套件决定执行提供方 |
| 图像处理 | `image` + `imageproc` + `nalgebra` + 自研算子 | 纯 Rust 栈，见 ADR-0001 |
| HTTP | `axum` | 仅存在于 `photos-api` |
| CLI | `clap` | 子命令 `process / serve / models` |
| 配置 | `toml` | `application.toml`，优先级：CLI > 环境变量 > toml > 默认值 |
| 存储 | `rusqlite`（WAL 模式） | `data/` 下任务历史 / 键值缓存 / 偏好 |
| 日志 | `tracing`/`tracing-appender` | 级别、格式、日轮转、32 天保留 |
| 桌面 | Tauri 2 | 仅 `photos-desktop` |
| 前端 | React 19 + Tailwind CSS + Zustand | 单页三区；本阶段不引入 ECharts（见 PRD 4.3） |
| 测试 | `cargo test` + 集成测试 | TDD，覆盖率 100%（见实施计划） |

### 为什么这样搭配（模型套件论证）

1. **RetinaFace + MoveNet 是姿态纠偏的基础组合**：RetinaFace 给出人脸框 + 5 关键点（眼角/鼻尖/嘴角），MoveNet 给出 17 个人体关键点（含左右肩）。两者融合才能算「头部倾斜角 + 肩线倾斜角」，这是 LiYing 纠偏逻辑核心。**只用面部 5 点无法校正肩膀一高一低。**
2. **BiRefNet-Lite 是 CPU 场景最优解**：Full 版在 CPU 单张可能 10s+，Lite 画质损失很小但快 3~5 倍。
3. **RMBG-1.4 作为极速档**：模型体积小（~170MB），推理快，发丝边缘略逊但满足粗略处理。
4. **MODNet 仅向下兼容**：在 `[models.modnet]` 注册但不进任何预设，高级用户可手动改配置启用。

## 3. 证件照处理流水线 pipeline

```
输入原图 (RGB/BGR，任意尺寸)
  │
  ▼
┌─────────────────────────────────────────┐
│  Step 1: 人脸检测 (RetinaFace / MTCNN)   │
│  输出: 人脸框 bbox + 5 面部关键点         │
└──────────────────┬──────────────────────┘
                   ▼
┌─────────────────────────────────────────┐
│  Step 2: 人体关键点检测 (MoveNet)         │
│  输出: 17 点坐标，重点取 left_shoulder    │
│        和 right_shoulder                  │
└──────────────────┬──────────────────────┘
                   ▼
┌─────────────────────────────────────────┐
│  Step 3: 姿态角度求解（移植 LiYing 逻辑）   │
│  · 头部角 θ_head = atan2(右眼-左眼)        │
│  · 肩线角 θ_shoulder = atan2(左肩-右肩)    │
│  · 融合 θ_final = 0.6*θ_head + 0.4*θ_shoulder │
│  · 自动阈值保护: |θ_final| > 22°            │
│    → 不自动纠偏，降级继续并返回告警          │
│  · 手动覆盖: 用户显式角度，上限 ±45°         │
│  输出: 旋转角 θ (弧度) + 旋转中心            │
└──────────────────┬──────────────────────┘
                   ▼
┌─────────────────────────────────────────┐
│  Step 4: AI 人像抠图                      │
│  (BiRefNet / RMBG，ONNX 推理)            │
│  · 预处理: resize + normalize             │
│  · 推理 → 概率 mask [0,1]                 │
│  · 后处理: 阈值化 + 形态学去噪（imageproc） │
│  输出: 与原图同尺寸的 alpha mask           │
└──────────────────┬──────────────────────┘
                   ▼
┌─────────────────────────────────────────┐
│  Step 5: 同步几何纠偏（关键优化）           │
│  · 用同一个仿射矩阵 M 同时变换:            │
│    - 原图（双三次/线性插值）               │
│    - alpha mask（最近邻，防边缘模糊）       │
│  · 避免先旋转再抠图导致的两次插值损失        │
│  输出: 扶正后的原图 + 扶正后的 mask         │
└──────────────────┬──────────────────────┘
                   ▼
┌─────────────────────────────────────────┐
│  Step 6: alpha 混合换底色                  │
│  · mask 边缘羽化（高斯模糊）               │
│  · out = fg * alpha + bg * (1 - alpha)    │
│  · 按底色列表循环执行，每色一张             │
│  输出: N 张换底效果图                       │
└──────────────────┬──────────────────────┘
                   ▼
┌─────────────────────────────────────────┐
│  Step 7: 可选后处理                        │
│  · 美颜: 双边滤波磨皮 + 肤色提亮 + 锐化    │
│    （自研算子）                           │
│  · 智能换装: 虚拟试衣模型（实验、默认关闭）  │
└──────────────────┬──────────────────────┘
                   ▼
┌─────────────────────────────────────────┐
│  Step 8: 裁剪 + resize 到证件标准尺寸      │
│  · 基于人脸框计算头顶/下巴位置              │
│  · 按 [sizes.xxx] 的宽高比中心裁剪          │
│  · resize 到目标像素（兰索斯，自研/回退）    │
└──────────────────┬──────────────────────┘
                   ▼
┌─────────────────────────────────────────┐
│  Step 9: 排版输出                          │
│  · 6寸 / A4 相纸自动拼版                   │
│  · floor((纸宽-margin*2)/(照宽+gap))      │
│    × floor((纸高-margin*2)/(照高+gap))    │
│  · 输出单张证件照 + 排版相纸图              │
└─────────────────────────────────────────┘
```

> Step 5 起 BGR→RGB 等色彩空间转换随插值库约定统一处理；实现细节不在此文约束。

## 4. 配置与数据

### 4.1 application.toml 结构

```toml
[general]        # data_dir、日志级别、默认模式等

[models.<id>]    # 注册表：path、sha256、input_dims、[可选] download.url
[models.download]# 下载清单：镜像地址、超时、并发

[modes.speed]    # face = models.mtcnn / keypoint = models.movnet_light / matting = models.rmbg
[modes.balanced] # face=RetinaFace / keypoint=MoveNet-Lightning / matting=BiRefNet-Lite
[modes.quality]  # face=RetinaFace / keypoint=MoveNet-Thunder / matting=BiRefNet-Full

[sizes.one_inch] # 名称、物理尺寸(mm)、dpi、像素、宽高比（一寸/二寸/小一寸…）
[backgrounds.*]  # 红/白/蓝/灰 = RGB 值
[layout.6inch]   # 纸张尺寸、边距、间距
[layout.a4]
[beauty]         # 磨皮、美白、提亮开关与强度
[mode]           # 默认套件
```

参数优先级：命令行 > 环境变量 > toml > 默认值（覆盖为部分覆盖，未命中的段沿用 toml 值）。

### 4.2 存储设计（sqlite，WAL 模式，位于 `data/`）

```
表 task_history
  id          INTEGER PK
  input_path  TEXT        -- 输入文件路径（不存像素）
  mode        TEXT        -- speed|balanced|quality
  size        TEXT        -- 尺寸标准标识
  backgrounds TEXT        -- "red,blue,white"
  beauty      TEXT        -- 美颜参数 JSON
  rotate      REAL NULL   -- 手动纠偏角度
  outputs     TEXT        -- 结果产物路径 JSON
  status      TEXT        -- 成功/失败/告警
  message     TEXT        -- 告警/错误（中文，脱敏）
  created_at  TEXT        -- 本地时间 YYYY-MM-DD HH:MM:SS.SSS

表 kv_cache            -- 模型校验等通用键值缓存
  key        TEXT PK
  value      TEXT
  updated_at TEXT

表 prefs
  key        TEXT PK
  value      TEXT
  updated_at TEXT
```

边界：**只存元数据，不存像素/人脸框/关键点坐标**。删除输入文件后历史自然失效。

## 5. 纠偏容错策略（B + C）

| 场景 | 行为 |
|---|---|
| \|θ_final\| ≤ 22° | 自动纠偏，正常出图 |
| \|θ_final\| > 22° 且未手动覆盖 | **不纠偏，降级继续出图**，Result 附告警 `角度超限，本次未自动纠偏（测量角 X°）` |
| 用户显式 `--rotate` / WebUI 滑块 | 用用户角度覆盖，上限 ±45°，正常出图 |

实现要点：自动判断不修改自动值；仅在用户显式 override 时使用传入值，core 无需两套旋转机制。

## 6. WebUI 前端（React 19）

### 6.1 状态与结构

- **Zustand store**：模式套件、尺寸、底色、美颜参数、任务队列（批量）、预览对比状态。
- 单页三区：上传区 → 参数面板 → 预览/结果区。
- 可选「历史任务」列表，数据来自 `GET /tasks`（读 `task_history`）。
- 下载：单张 / 6寸排版 / A4 排版 / 批量打包。

### 6.2 交互原型

```
[拖拽上传区] → 校验→ 参数面板绑定 Zustand → POST /tasks  →
预览/结果区：左原图右结果（对比滑块） → 下载按钮（blob）
```

## 7. API 契约（photos-api）

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/tasks` | 提交处理请求（multipart 图片 + JSON 参数），返回任务 id |
| GET  | `/tasks/{id}` | 轮询任务状态与产物清单 |
| GET  | `/tasks/{id}/output` | 下载指定产物（单张/排版/打包 zip） |
| GET  | `/tasks` | 历史任务列表 |
| GET  | `/models` | 模型注册表与校验状态 |
| GET  | `/config` | 模式/尺寸/底色/布局 选项（驱动前端下拉） |
| GET  | `/ping` | 健康检查 |

事件：批量任务进度用轮询（200ms 粒度）足够，不引入 webhook/SSE 复杂度。

## 8. 质量与非功能架构约束

- 依赖单向、pub 收敛、边界清晰；`photos-core` 内部按 DDD 四层（领域/应用/基础设施/接口）划分模块。
- 所有错误为中文；错误链统一 `thiserror`；敏感字段脱敏于日志层。
- 测试：TDD；单元（算子/角度求解/配置合并）、API（axum 契约）、集成（pipeline 全链路）、系统（CLI 端到端）。
- 编译优化（release 开 LTO、strip、panic=abort）以减小体积。
