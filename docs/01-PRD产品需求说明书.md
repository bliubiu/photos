# 智能证件照工具 产品需求说明书

> 版本：2026.09.16.4（CalVer）
> 状态：已评审（经设计访谈逐项确认）
> 关联文档：`CONTEXT.md`（领域术语）、`02-架构设计.md`、`03-实施计划.md`、`docs/04-模型清单.md`、`docs/05-API契约.md`、`docs/06-安全设计.md`、`docs/adr/0001-纯Rust图像栈.md`

## 1. 产品概述

**智能证件照工具**是一款**纯本地离线、高性能、高精度**的证件照全自动处理工具。它向上是一套**通用人像处理引擎**（智能抠图、姿态纠偏、换底、美颜、裁切、排版），证件照规范输出是其中一个核心场景。

- **双运行形态**：CLI 命令行批量处理 + Tauri 桌面 WebUI 可视化操作（WebUI 背后是本地 Axum HTTP 服务）。
- **双产物出口**：一次处理既可产出经典证件照（单张 + 排版相纸），也可独立产出通用效果图（抠图换底图、美颜图）。
- **三模式傻瓜式模型套件**：用户仅按设备场景选「极速 / CPU 高性能 / GPU 高质量」，底层模型组合由预设自动加载，专业用户仍可自定义。
- **核心理念**：处理全程零联网；用户不接触任何 AI 模型细节。

## 2. 目标用户与场景

| 用户群 | 典型场景 | 对应模式 |
|---|---|---|
| 小白用户 | 手机拍生活照快速出一张证件照 | CPU 高性能（默认） |
| 政务/报名/签证 | 有规范要求的标准证件照，要求画质与发丝细节 | GPU 高质量 |
| 低配机器批量流水线 | 大批量粗处理、快速出图 | 极速 |
| 服务器/自动化脚本 | `photos process` / `photos serve` 无头批量 | 任意（按设备） |

## 3. 核心概念与术语

领域术语以 `CONTEXT.md` 为准，关键约定：

- **照片/图片**：用户输入素材，不是独立产品线。
- **人像处理**：通用处理能力（抠图、换底、美颜、几何纠偏），可独立使用。
- **证件照**：面向证件规范的成品输出（标准尺寸、规范底色、排版相纸）。
- **模式套件（Speed/Balanced/Quality）**：三套预设模型组合，屏蔽底层模型细节。
- **姿态纠偏**：头部姿态角与肩线角度加权融合的旋转校正。
- **排版**：按 6 寸 / A4 相纸规格计算行列数拼版。

## 4. 功能需求

### 4.1 通用功能（两种入口共用，由 `photos-core` 提供）

- 单图处理、文件夹批量处理。
- 三模式套件选择（speed / balanced / quality）。
- 标准尺寸裁切（一寸/二寸等，尺寸集见 `TOML` 配置）。
- 底色列表支持 1..N 个，一次处理出齐（红/白/蓝/灰/自定义 RGB）。
- 美颜：磨皮、美白、提亮（开关 + 强度可调）。
- 智能换装：正装替换（实验性功能，默认关闭）。
- 结果输出：通用效果图（可选）+ 每底色各一张证件照（可选）+ 排版相纸（可选）。

### 4.2 CLI 命令行模式

整体形态：`photos <子命令> [选项]`，无 GUI 依赖，适配服务器、自动化脚本、批量运维。

| 子命令 | 用途 | 关键参数 |
|---|---|---|
| `photos process` | 单图 / 文件夹批量处理 | `-m/--mode speed|balanced|quality`、`-s/--size 一寸`、`-b/--backgrounds red,blue`、`--beauty 开关+强度`、`--rotate 手动纠偏角度`、`--layout 6inch|a4`、`-o/--out 目录` |
| `photos serve` | 启动本地 HTTP 服务（复用 `photos-api`） | `--host 127.0.0.1`、`--port 随机` |
| `photos models` | 列出模型清单与校验状态 | 无 |

参数凡出现于请求契约的，与 HTTP 端同义、同界。

### 4.3 WebUI 桌面模式（Tauri2 + React 19）

- 本地桌面窗口，不与浏览器挂钩；后台内嵌 Axum 监听 `127.0.0.1` 随机端口，前端无感知调用。
- 界面极简，单页三区：

```
┌──────────────────────────────────────────────┐
│ [拖拽上传区域]  点击选择图片（支持批量）        │
├──────────────────────────────────────────────┤
│ 运行模式: [CPU 高性能 ▼]（仅 3 个选项+说明文字）│
│ 证件尺寸: [一寸 ▼]                             │
│ 背景颜色: [白][蓝][红][灰][自定义色板]         │
│ 美颜:     [开关] 磨皮[---●--] 提亮[---●--]    │
│ 智能换装: [开关]（默认关闭，实验性提示）        │
├──────────────────────────────────────────────┤
│ [原图预览]        [处理结果预览]               │
│ (可左右对比滑块)   (可缩放)                     │
├──────────────────────────────────────────────┤
│ [下载单张] [下载6寸排版] [下载A4排版] [打包下载]│
└──────────────────────────────────────────────┘
```

- **历史任务列表（M3 必含）**：展示 `task_history` 记录（输入文件、模式、尺寸、底色、结果路径、状态、耗时），纯列表，无图表。
- 批量上传、批量处理、打包下载。

### 4.4 任务模型（单请求多产物）

- 一次请求 = 一份输入照片 + 参数集；一次响应 = 多个产物文件。
- 重计算（人脸检测、姿态求解、AI 抠图、同步纠偏）只做一次；换底色是廉价 alpha 混合，按底色数量重复执行。
- 结构：`Photo → Request → Result`，详见 `02-架构设计.md` 领域模型。

### 4.5 姿态纠偏规则

- 融合角：头部角权重 0.6、肩线角权重 0.4。
- **自动纠偏阈值 ±22°**：超限则**不自动纠偏，降级继续出图**并返回告警（不阻断任务）。
- **手动角度覆盖（`--rotate` / WebUI 滑块）**：由用户显式指定目标角度，上限 **±45°**；用户明示意愿高于自动保护阈值。

### 4.6 模型管理（本地目录发现 + 可选下载）

- 模型存放于 `项目根目录/models`。
- 元数据在 `application.toml` 的 `[models.<id>]` 段（path、sha256、输入张量维度、可选下载地址）。
- 完整性校验：**惰性校验 + 结果缓存**（首次使用某模型时校验，校验结果按「路径+mtime+size」缓存入 sqlite，变化才重校验）。
- 缺失或校验失败 → 提示用户「手动放置」或「一键下载」，**下载为可选便利，不破坏离线属性**。
- 已注册但不进预设：MODNet（兼容保留，专业用户可改配置启用）。

## 5. 三套模型套件定义

| 维度 | 极速 Speed | CPU 高性能 Balanced（默认） | GPU 高质量 Quality |
|---|---|---|---|
| 目标场景 | 低配机器 / 批量粗处理 | 日常本机、笔记本 CPU | N 卡离线精修、画质优先 |
| 人脸检测 | MTCNN | RetinaFace | RetinaFace |
| 人体关键点 | MoveNet-Lightning | MoveNet-Lightning | MoveNet-Thunder |
| 人像分割 | RMBG-1.4 | BiRefNet-Lite | BiRefNet-Full |
| 推理后端 | ONNX Runtime CPU | ONNX Runtime CPU | ONNX Runtime CUDA |
| 典型单张耗时 | 0.8~1.5s | 2~4s | 0.5~1s |
| 发丝精度 | 一般 | 良好 | 极佳 |
| 内存占用 | ~800MB | ~1.5GB | ~3GB 显存 |
| MODNet | 不启用 | 不启用 | 不启用 |

> 无 CUDA 设备时 quality 套件自动降级为 CPU 推理并返回告警，不阻断任务。
>
> 为什么不这样搭配的理由论证，见 `02-架构设计.md`。

## 6. 图像后处理

- **智能换底色**：RGB 自定义色值 + 常用证件底色（红/白/蓝/灰）一键切换。
- **AI 美颜**：磨皮、美白、提亮、肤色均衡，可开关、强度可调。实现以纯 Rust 传统算法为主（双边滤波等自研算子），AI 美颜 ONNX 模型作为扩展可选，默认不启用。
- **智能换装**：正装替换，适配证件照规范（实验性，默认关闭，UI 提示）。

## 7. 非功能需求

### 7.1 性能与资源

- 各套件典型单张耗时见上表；批量场景要求吞吐优先于单张极致优化。
- 内存占用可控（对齐上表预算），超标预案见实施计划 M4。
- 编译配置优化，从源头减小体积。

### 7.2 离线与私密

- **处理全程零联网**（模型供给的首次下载为可选前置，事后处理不联网）。
- **数据最小留存**：数据库只存任务元数据（路径/参数/状态/耗时）与内部键值缓存，**绝不落库图像像素、人脸框、关键点坐标等画像级数据**。
- 日志脱敏、错误信息全中文、禁止明文敏感值，遵循 `docs/06-安全设计.md`。

### 7.3 配置

- 统一 `application.toml`：全局、三套模型套件、模型注册表、尺寸集、底色集、排版规格、美颜参数、日志级别等。
- 参数优先级：**命令行 > 环境变量 > toml 配置文件 > 默认值**。

### 7.4 日志

- 级别 DEBUG/INFO/ERROR，默认 INFO。
- 格式 `[YYYY-MM-DD HH:MM:SS.SSS] [级别] [线程ID或进程ID] [模块:行号] - 内容`。
- 文件按日轮转、保留 32 天，存 `logs/photos-YYYYMMDD.log`，同时可输出终端。

### 7.5 数据持久化

- `data/` 目录下 sqlite（WAL 模式），含：`task_history`（任务记录）、`kv_cache`（模型校验等通用缓存）、`prefs`（用户偏好）。

### 7.6 质量约束

- DDD 四层架构、依赖单向、边界清晰、pub 收敛。
- TDD：核心算法与状态机追求高覆盖（目标 100%）；API 契约全端点覆盖；系统层以场景验收为主，不以全仓行覆盖 100% 为门槛。
- 每次变更必须对应 git commit；重要不可逆技术决策落 `docs/adr/`。
